  <name>Task 1: Create c14/story/validate.py + tests/test_validate.py</name>
  <files>c14/story/validate.py, tests/test_validate.py</files>
  <action>
Create the pure graph-algorithm module (reachability + validation + claim-id collection) and its unit tests. Python 3.6 stdlib ONLY (`json`, `os`, `collections`). NO pymol/PyQt5 imports. The reachability/validate functions operate on a `nodes` dict (either `{id: Node}` or `{id: raw_dict}`) — they are pure algorithms with no file I/O, so they're trivially unit-testable with inline fixtures. `check_reachability(nodes, start_id)` and `validate_graph(nodes)` both accept a `{id: node}` dict as their `nodes` argument — this is the exact shape Plan 02's `StoryGraph.all_nodes()` returns (pinned to the dict, not a list), so Plan 05 can pass `g.all_nodes()` directly to these functions. `collect_claim_ids` does its OWN minimal file loading (reads a single file OR a manifest+files bundle) so it is independent of `c14.story.graph` — this keeps Plan 03 parallel with Plan 02 (no import of graph.py, which is created in Plan 02).

**`c14/story/validate.py`** — module docstring: "Graph validator + reachability checker + claim-id collector. Pure-Python algorithms, stdlib only. The reachability checker establishes the 'all endings reachable' invariant (Pitfall 8). collect_claim_ids is the Phase 2 home of the gate's story-walker (forward-compatible with Phase 1's inline walker)."

Plain classes + functions:
- `class Issue(object)` — `__init__(self, kind, node_id, detail=None)`. `kind` is a string ("dangling_divert"|"unreachable_ending"|"unknown"). `__repr__`.
- `class ReachabilityReport(object)` — `__init__(self, start_id, all_endings, reachable_endings, unreachable_endings)`. Store lists of ending node ids. Property `is_ok` → `len(self.unreachable_endings) == 0`. `__repr__` (e.g. "ReachabilityReport(start=..., reachable=[...], unreachable=[...], ok=True/False)").

- `def check_reachability(nodes, start_id)` — pure BFS/DFS over the graph:
  1. Build an edge list: for each node, for each choice, the edge is `node_id → choice.goto` (if goto is not None). (Access via `node.choices` if Node objects, or `node["choices"]` if raw dicts — support BOTH: write a small helper `_choices(node)` that returns `node.choices if hasattr(node,'choices') else node.get('choices', [])` and `_goto(choice)` similarly. This makes the function work on both Node objects (from graph.py) and raw JSON dicts (from collect_claim_ids fixtures).)
  2. BFS/DFS from `start_id`, collecting all reachable node ids. (Use `collections.deque` for BFS, or a set + stack for DFS — either is fine.)
  3. Identify endings: a node is an ending if `is_ending` is not None (`_is_ending(node)` helper: `getattr(node,'is_ending',None) is not None or node.get('is_ending') is not None`).
  4. `reachable_endings = [e for e in all_endings if e in reachable_set]`, `unreachable_endings = [e for e in all_endings if e not in reachable_set]`.
  5. Return `ReachabilityReport(start_id, all_endings, reachable_endings, unreachable_endings)`.
  Edge case: if `start_id` not in nodes, return a report with all endings unreachable (is_ok False) — or raise KeyError; prefer returning a report with unreachable_endings = all_endings (graceful, lets the checker report the problem).

- `def validate_graph(nodes)` — return a list of `Issue`:
  - For each node, for each choice with a non-None goto: if `choice.goto not in nodes` → `Issue("dangling_divert", node_id, detail="choice → {}".format(goto))`.
  - (Other checks can be added later; for Phase 2, dangling diverts is the key one.)
  - Return the list (empty list = valid graph).

- `def collect_claim_ids(story_path)` — the gate's story-walker, Phase 2 home. Accepts EITHER:
  - A `.json` FILE: `json.load` it, get `nodes = data.get("nodes", {})`, validate it's a dict, return `{node_id: list(node.get("claim_ids", []))}` (same as Phase 1's `collect_referenced_claim_ids` — backward-compatible).
  - A DIRECTORY: read `os.path.join(story_path, "manifest.json")`, get `files` list; for each file, `json.load(os.path.join(story_path, f))`, merge its `nodes` dict; collect claim_ids from all merged nodes; return `{node_id: list(claim_ids)}`.
  - Detect file vs directory via `os.path.isdir(story_path)`. If neither (path doesn't exist), raise `ValueError` (the gate maps this to exit 2).
  - Raise `ValueError` on bad schema (non-dict nodes, non-dict node entry) — same contract as the Phase 1 walker so the gate's exit-2 path still works.
  - This function does its OWN minimal loading (does NOT import `c14.story.graph`) to stay independent of Plan 02. (The minor manifest-reading overlap with graph.py is an acceptable trade for module independence + parallel execution.)

**`tests/test_validate.py`** — `class TestValidate(unittest.TestCase)`:

Use inline node fixtures (raw dicts — the simplest form; proves the functions work on raw JSON shapes, same as the gate sees):
- Helper `_node(id, choices=None, claim_ids=None, is_ending=None)` — returns a raw dict `{"id": id, "choices": choices or [], "claim_ids": claim_ids or [], "is_ending": is_ending}`.
- Helper `_choice(goto=None, weight=None)` — returns `{"goto": goto, "weight": weight}`.
- `test_reachability_green` — build a well-formed graph: `{"a": _node("a", [_choice("b"), _choice("c")]), "b": _node("b", is_ending="good"), "c": _node("c", is_ending="bad")}`. `check_reachability(nodes, "a")` → `is_ok` True, `reachable_endings == ["b","c"]`, `unreachable_endings == []`.
- `test_reachability_red_orphaned` — orphan an ending: `{"a": _node("a", [_choice("b")]), "b": _node("b", is_ending="good"), "c": _node("c", is_ending="bad")}` (c has no incoming edge). `check_reachability(nodes, "a")` → `is_ok` False, `"c" in unreachable_endings`, `"b" in reachable_endings`.
- `test_reachability_multi_hop` — a→b→c→ending (chain); all reachable; is_ok True.
- `test_reachability_missing_start` — `check_reachability({"a": _node("a",is_ending="good")}, "zzz")` → is_ok False, all endings unreachable (graceful, not a crash).
- `test_validate_graph_dangling_divert` — `{"a": _node("a", [_choice("nonexistent")])}` → `validate_graph(nodes)` returns one Issue with kind "dangling_divert" and node_id "a".
- `test_validate_graph_clean` — well-formed graph → `validate_graph` returns `[]`.
- `test_collect_claim_ids_file` — write a temp single-file story (same shape as `tests/fixtures/story_pass.json`: `{"nodes": {"n1": {"claim_ids": ["c1"]}, "n2": {"claim_ids": ["c2","c3"], "is_ending":"true"}}}`) to a tempdir; `collect_claim_ids(path)` returns `{"n1": ["c1"], "n2": ["c2","c3"]}`. (Backward-compatible with Phase 1 fixtures.)
- `test_collect_claim_ids_directory` — write a temp directory with `manifest.json` (`{"files":["x.json"]}`) + `x.json` (`{"nodes": {"n1": {"claim_ids":["c1"]}}}`); `collect_claim_ids(dir)` returns `{"n1": ["c1"]}`. (New multi-file capability.)
- `test_collect_claim_ids_bad_schema_raises` — `collect_claim_ids` on a file with `{"nodes": "not a dict"}` raises `ValueError` (gate maps to exit 2).
- `test_collect_claim_ids_nonexistent_raises` — `collect_claim_ids("does/not/exist")` raises `ValueError` (or OSError — gate catches both).
- Use `tempfile.mkdtemp()` for temp dirs/files; clean up in `tearDown`.
- Import via `from c14.story.validate import check_reachability, validate_graph, collect_claim_ids, ReachabilityReport, Issue`.
