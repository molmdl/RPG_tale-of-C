Adopt the ARCHITECTURE.md Pattern 2 `StoryInterpreter` design near-verbatim, with these concrete decisions:

**`c14/story/interpreter.py`** — `class StoryInterpreter(object)`. Module docstring: "Walks the story graph: evaluates choice conditions, picks weighted (RNG) branches, runs on_enter MolActions (pure data), records visit counts, detects endings. Pure-Python, no pymol — emits MolAction lists, never cmd.* calls."

Key requirements:
- `pick_choice(self, node, state, rng)` — adopt the ARCHITECTURE.md Pattern 2 `pick_choice` near-verbatim:
  1. `eligible = [c for c in node.choices if self._cond(c.cond, state)]` (filter by condition).
  2. `weighted = [c for c in eligible if c.weight is not None]`.
  3. If `weighted`: pick deterministically via the single RngEngine — `total = sum(c.weight for c in weighted); r = rng.random() * total; upto = 0.0; for c in weighted: upto += c.weight; if r <= upto: return c` (return the picked Choice). (If `total == 0` or no weighted, fall through to return eligible.)
  4. Else (non-weighted): `return eligible` (the list — caller/player selects by index).
  Note: a node can have ALL weighted (RNG decides, like intro.start) or a mix. When all are weighted, `pick_choice` returns a single Choice (the RNG pick). When some are non-weighted, it returns the eligible list.
- `enter_node(self, node, state, rng)` — adopt the ARCHITECTURE.md `enter_node` behavior:
  1. `state.record_visit(node.id)` (visit_counts++ — for conditions + cycle-trap detection).
  2. Collect the MolAction list: `actions = list(node.on_enter)` (these are already MolAction objects from Node.from_dict; return them — the caller/controller dispatches to the pymol_layer; in tests, the mock sink collects them).
  3. If `node.is_ending is not None`: `state.mark_finished(node.is_ending)` (sets finished + ending_tier). (No choices to present at an ending.)
  4. Return `actions` (the MolAction list). (Do NOT call any cmd.* — return pure data.)
  (Text-variant expansion (sequence/cycle/shuffle) is deferred — the minimal story has no `text_variants`; if `node.text_variants` is present, a future plan handles it. For Phase 2, `enter_node` does not need variant logic.)
- `_cond(self, cond, state)` — safe condition evaluator. If `cond is None`: return True (always eligible). Else: evaluate `cond` against the state with a **restricted namespace** — `eval(cond, {"__builtins__": {}}, {"flags": state.flags, "char": state.character, "counters": state.counters, "visits": state.visit_counts})`. SECURITY: story content is trusted (bundled, authored by the team, not user input), and the namespace has no builtins, so `eval` is bounded to reading state fields. This handles the architecture's example `"not seen_tca and char=='glucose'"` (note: use `char` not `character` in the namespace, matching the architecture's example). Wrap in try/except: on any exception, return False (a malformed condition silently disables the choice — fail-safe, never crash the game). Document this security model in the docstring.
- `apply_effects(self, choice, state)` — apply a choice's `effects` dict: if `effects` has `"set"` (a dict of flag→value), call `state.set_flag(k, v)` for each; if `"incr"` (a dict of counter→delta), call `state.incr(k, v)` for each. (Used by the engine after a choice is made; keep it here so the interpreter owns effect semantics.)
- Add `__repr__`.
- Import: `from c14.story.model import Node, Choice, MolAction` (for type hints/docstring clarity — not strictly needed at runtime). No pymol/PyQt5. No `random` import (the rng is passed in — dependency injection).
