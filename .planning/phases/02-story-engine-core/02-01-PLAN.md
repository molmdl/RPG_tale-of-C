<objective>
Create the three pure-Python foundation modules that everything else in Phase 2 builds on: the story data model (`c14/story/model.py`: Node, Choice, MolAction), the seedable RNG (`c14/rng.py`: RngEngine), and the saveable game state (`c14/state.py`: GameState). These three are independent of each other (no cross-imports) and have zero dependencies beyond the stdlib, so they form Wave 1.

Purpose: This is the "PHASE-0 (no deps)" group from ARCHITECTURE.md's build order. MolAction is the testability-boundary carrier — pure data that the future pymol_layer translates to `cmd.*`, so the domain never imports pymol. RngEngine is the single seeded PRNG instance that ALL stochastic draws must use (Anti-Pattern 7: ad-hoc `random.random()` breaks classroom reproducibility). GameState is the saveable unit whose JSON round-trip (including RNG seed + state) makes save/load possible. Getting these three right — simple, stdlib-only, 3.6-safe, import-clean — de-risks the interpreter, engine, and save/load built on top of them.

Output: `c14/story/__init__.py`, `c14/story/model.py`, `c14/rng.py`, `c14/state.py`, `tests/test_model.py`, `tests/test_rng.py`, `tests/test_state.py`.

**`c14/rng.py`** — `class RngEngine(object)`. Module docstring: "Seedable PRNG for the game. Single random.Random instance per playthrough. Fixed-seed (demo) and random-seed (play) modes. State is JSON-serializable for save/load (Anti-Pattern 7 mitigation). Pure-Python, stdlib only."

Key requirements:
- `__init__(self, seed=None)` — if `seed is None` (random/play mode): pick a non-deterministic seed via `secrets.randbits(31)` (or `os.urandom`-derived int) and store `self._seed`; else (fixed/demo mode): store `self._seed = seed`. Create `self._rng = random.Random(self._seed)`. Record the mode implicitly via whether seed was provided.
- `@property seed` — returns `self._seed` (int). This is saved with the game so a run is replayable.
- `random(self)` — `return self._rng.random()`. (The interpreter's weighted-pick uses this per ARCHITECTURE.md Pattern 2.)
- `weighted_pick(self, items, weights)` — convenience: `return self._rng.choices(items, weights=weights, k=1)[0]` (3.6+). Returns one picked item. (Provided for callers that prefer `random.choices`; the interpreter may instead use `random()` + manual cumulative sum per the architecture — either is fine.)
- `get_state(self)` — return a JSON-serializable dict: `{"version": st[0], "state": list(st[1]), "gauss_next": st[2]}` where `st = self._rng.getstate()`. (Tuples→lists so `json.dump` works.)
- `set_state(self, state_dict)` — `self._rng.setstate((state_dict["version"], tuple(state_dict["state"]), state_dict["gauss_next"]))`. (Lists→tuples for `random.Random.setstate`.)
- `@classmethod from_state(cls, seed, state_dict)` — construct an RngEngine and restore its state: `eng = cls(seed); eng.set_state(state_dict); return eng`. (Used on load to rebuild the exact PRNG position.)
- Add `__repr__` (e.g. `"RngEngine(seed={})".format(self._seed)`).

Use `.format()` or f-strings. No `@dataclass`. No walrus. No `from __future__ import annotations`.
