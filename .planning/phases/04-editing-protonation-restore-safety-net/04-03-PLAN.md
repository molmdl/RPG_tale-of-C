<objective>
Build the **ProtonationManager** (curated-variant protonation, NO pH engine — CAST-03 settled decision) + the **protonation_catalog** (pure-data variant table). This satisfies SC4 ("ProtonationManager applies a curated protonation variant for at least one approved example, and a user-adjustable switch between curated variants is exercisable") and ensures EDIT-05 (restore safety net) covers protonation changes.

Purpose: The settled decision (PROJECT.md, CAST-03) is that the game ships **curated protonation variants**, NOT a pH/pKa engine. This is forced by PyMOL reality: `cmd.h_add` is valence-only (not pH-aware — confirmed by its docstring editing.py:1220), there is NO `cmd.h_remove` (use `cmd.remove` with H-targeted selection), and NO bundled propka/pKa/pH module (exhaustive grep of tmp/pymol-src/modules/pymol/). ProtonationManager is a thin dispatcher: it looks up a variant in the pure-data catalog and delegates the actual cmd.alter / cmd.h_add / cmd.remove / cmd.sort / cmd.rebuild to `edit_ops.apply_edit` (04-01) — keeping the alter gate allowlist at exactly ONE module and guaranteeing backup/restore covers every protonation change.

**Critical coordination with 04-01:** ProtonationManager calls `edit_ops.apply_edit(object_name, edit_steps)` where `edit_steps` is a list of dicts each with an "op" key ("alter" | "h_add" | "remove") and "sele"/"expr" keys. The apply_edit signature was settled in 04-01 as `apply_edit(object_name, edit_steps) -> RestoreHandle`. ProtonationManager composes its own step list from the catalog's h_ops.

**Phase 4 boundary:** ships the MECHANICS + a PLACEHOLDER histidine example (HID/HIE/HIP standard AMBER nomenclature, claim_id="PLACEHOLDER_PHASE5"). NO pKa values, NO DOIs, NO "this is the active tautomer for enzyme X" claims — those are Phase 5+ cited content (CITE-01). The `test_phase4_placeholder_claim_ids` + `test_no_pka_values_in_catalog` guards enforce this boundary.
</objective>

**Methods to implement:**
- `__init__(self, cmd, edit_ops, catalog, assets)` — store the 4 deps; `self._current = {}` (target → variant_id switch state); `self._backup = {}` (target → RestoreHandle or backup_name, for restore).
- `list_variants(self, target)` — return `self._catalog.variants_for(self._residue_key(target))`. (Phase 4: target IS the residue key, e.g. "HIS"; Phase 5+ target schema may need parsing — note this in a comment.)
- `current_variant(self, target)` — return `self._current.get(target)` (None if no variant applied).
- `apply_variant(self, target, variant_id)` — the SC4 entry point. Look up `spec = self._catalog.lookup(self._residue_key(target), variant_id)` (raises KeyError if missing — delegated to catalog). If `spec["mode"] == "load"`: call `self._apply_load(target, spec)`. Else: call `self._apply_alter(target, spec)`. Record `self._current[target] = variant_id`. Return variant_id.
- `switch_variant(self, target, variant_id)` — alias for apply_variant (the user-adjustable SC4 switch; kept as a distinct name so the SC4 mapping is explicit in the UI). Every switch takes a fresh backup so it is reversible (EDIT-05).
- `restore(self, target)` — EDIT-05 restore. Delegate to `self._edit.restore(target)` (the 04-01 EditOps.restore looks up the handle + verifies atom count + residue signature). Clear `self._current[target]` and `self._backup[target]`. Raises RuntimeError if no backup was registered (edit_ops.restore raises this).
- `_residue_key(self, target)` — Phase 4 placeholder: return target verbatim (target IS the residue key like "HIS"). Add a comment: Phase 5+ target schema (e.g. "pdb:1TNR/chainA/HIS123") may need parsing; coordinate with the edit-node contract (Phase 5.1).
- `_apply_load(self, target, spec)` — Mode (a): replace the object with a pre-built protonated structure. Take a backup FIRST via `self._edit.take_backup(target)` (so restore works — EDIT-05); then `self._cmd.delete(target)` (src: commanding.py:496); then `self._assets.load_bundled(spec["source_file"], target)` (AssetManager Phase 3). Store the handle in `self._backup[target]`. NO alter (the .pdb is pre-built). NOTE: the `# src:` citation goes on the cmd.delete call (the only direct self._cmd.* call here; load_bundled is in asset_manager.py).
- `_apply_alter(self, target, spec)` — Mode (b): build the edit_steps list with the CORRECT order (Pitfall 2: removes BEFORE alter, adds AFTER alter) and delegate to `self._edit.apply_edit(target, steps)`:
  1. `removes` = [{"op":"remove","sele":h["sele"]} for h in spec.get("h_ops",[]) if h["op"]=="remove"]
  2. `alter` = [{"op":"alter","sele":target,"expr":"resn='{}'".format(spec["resn"])}]
  3. `adds` = [{"op":"h_add","sele":h["sele"]} for h in spec.get("h_ops",[]) if h["op"]=="add"]
  4. `steps` = removes + alter + adds
  5. `handle = self._edit.apply_edit(target, steps)` (edit_ops takes the backup + dispatches + sorts + rebuilds + returns RestoreHandle)
  6. `self._backup[target] = handle`

  IMPORTANT: the "add" h_op maps to the "h_add" step op (NOT "add" — edit_ops.apply_edit's step dispatch recognizes "alter"|"h_add"|"remove"|"fuse"). The catalog h_ops use "add" (human-readable); the step dict uses "h_add" (the edit_ops step op). This translation happens in _apply_alter.
