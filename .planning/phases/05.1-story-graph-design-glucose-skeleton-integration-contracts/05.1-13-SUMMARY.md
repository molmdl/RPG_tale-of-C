## Decisions Made
- **Per-character shell node (intro.shell_glucose), NOT parametric:** a dedicated shell node per character, not a single parametric node loading the character-specific substrate from a state flag. Rationale: less duplication for glucose; the Phase 5.1 OQ7 "char-setting mechanism" (controller sets state.character) is not needed for the shell beat. FA/Alc get their own shell nodes in Phase 8 (the existing fa.stub/alc.stub return to intro.select for now; Phase 8 adds intro.shell_fa / intro.shell_alc between intro.select and the stubs, OR replaces the stubs).
- **Hide-20-AA approach: gly.start on_enter hide_all + show_as glucose, NOT a dedicated journey_start node:** gly.start's hide_all hides EVERYTHING (the 20-AA cast + the glucose shell loaded in intro.shell_glucose); then show_as glucose re-shows ONLY the hero's glucose molecule. This achieves "only the hero's molecule remains" (the 20 AA step back, the hero's shell persists) WITHOUT adding a dedicated intro.journey_start node. Rationale: simpler; gly.start already does hide_all, and the glucose object persists from intro.shell_glucose (molops hide_all -> cmd.hide, NOT cmd.delete).
- **0-single-Continue invariant UNCHANGED (NOT re-scoped):** the 2 new preface nodes each get a Continue + an Observe (mc:observe) 2nd choice (same-destination, different-experience, per the Continue-to-MC pattern from Plans 07-09). The invariant test is NOT re-scoped — the preface nodes are subject to it and comply (2 choices each, 0 single-Continue).
- **20-AA cartoon representation:** show_as with rep "cartoon" (cartoon naturally hides the terminal N-term/C-term groups). The exact cmd selection/hide is Phase 5.2/6; the skeleton carries the op name + target object placeholder.
- **Skeleton carries on_enter MolAction PLACEHOLDERS using the EXISTING MolOps op vocabulary** (hide_all, load, show_as — see c14/pymol_layer/molops.py). The exact cmd.* args (representation, selection strings, the hero-atom load convention) are Phase 5.2/6. The TBD_* PDB targets (pdb:TBD_HERO_CARBON, pdb:TBD_AA_CAST_20, pdb:TBD_GLUCOSE) follow the TBD_ACONITASE precedent (loud-fail at runtime until Phase 6/7 resolves them — NO fabricated PDB IDs). text_dramatic/text_teaching are Phase 7 (PLACEHOLDER_PHASE7 claim_ids).
