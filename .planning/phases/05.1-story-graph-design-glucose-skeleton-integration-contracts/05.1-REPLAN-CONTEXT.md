## 1. The Restoration Narrative (decided 2026-08-19)

**Source:** PROJECT.md Key Decisions row 109; spec.md Description NOTE (2026-08-19).

The hero is a "gifted/blessed" carbon — beyond an ordinary carbon atom, the hero has
the special power to edit/restore enzymes. The host organism is sick: enzymes are
malfunctioning (mutated/diseased). The hero journeys through the respiratory pathway
not only to reach a personal destiny (the ending tiers) but to save the host by
restoring the broken enzymes encountered at edit-allowed nodes.

**How it works mechanically (already built — Phase 4 EditRouter):**

| Player action | EditRouter outcome | Narrative frame |
|---------------|-------------------|-----------------|
| Correct reverse-mutation (matches `edits.json` signature) | known → branch node | "You restored the enzyme!" |
| Wrong mutation (no match) | unknown → bad-ending pool | "You made it worse." |
| Break a critical residue | → `bad.critical_residue_break` | "You destroyed the active site." |

The NEW element is the **on_enter pre-edit**: the enzyme is shown in its DISEASED
state when the player arrives (load wild-type PDB → `apply_edit` disease mutation).
The player sees the broken enzyme and attempts to fix it. The `apply_edit` helper
(Phase 4) already supports this (load → alter → sort → rebuild).

**Geometry caveat:** `cmd.alter` changes residue identity but does not repack side
chains or relax geometry. The "mutated" structure has correct sequence but approximate
3D coordinates. `text_teaching` should note this is a simplified representation.

## 2. Disease-Mutant Research Requirements

### What counts as a disease mutant

- **YES:** Point mutations (missense, nonsense) in the coding sequence that cause a
  recognized disease phenotype. Examples: IDH1 R132H (glioma), PKLR R479W (pyruvate
  kinase deficiency / hemolytic anemia), LDHA R171H (glycogen storage disease XI).
- **NO:** Splice variants (different mRNA isoforms — not a point mutation).
- **NO:** Silent polymorphisms with no disease association.
- **NO:** Fabricated/hypothetical mutations. Every mutation must trace to a real
  source (OMIM, ClinVar, UniProt, a peer-reviewed paper) and pass the per-claim
  approval gate.

### What to find per enzyme

For each enzyme in the pathway, determine:
1. **Does a known disease-causing point mutation exist?** (OMIM, ClinVar, UniProt
   variant pages)
2. **Is there a PDB structure of the MUTANT (not just wild-type)?** (RCSB search)
3. **If no mutant PDB:** can the mutation be applied at runtime via `cmd.alter`?
   (yes — the `apply_edit` helper does this; the structure will have correct sequence
   but approximate geometry)
4. **What is the reverse-mutation (the "correct fix" the player should perform)?**
   This becomes the `edits.json` known-edit signature for the EditRouter.
5. **What disease does it cause?** (for the `text_dramatic` / `text_teaching` — the
   narrative stakes)

## 3. "Continue" → MC Directive (user decision 2026-08-19)

**User directive:** "those 'continue' change to MC, others defer to playtest for now"

The current skeleton has many nodes with a single "Continue" choice (linear
progression — the player clicks Continue repeatedly through long enzyme chains).
This causes click-fatigue. The user wants EVERY "Continue" node converted to a
real multiple-choice (≥2 options).

### What this means structurally

Every node that currently has a single `{"label": "Continue", "goto": "next.node"}`
choice should gain a SECOND (or third) choice. The key constraint: in a linear
pathway (e.g. glycolysis is a linear chain — glucose MUST go to G6P, then to F6P,
etc.), the alternatives can't offer a different DESTINATION (the biochemistry is
fixed). So the MC options must differ in the EXPERIENCE, not the destination.

### Possible MC patterns (design decision for the replan session)

| Pattern | Option A | Option B | Same destination? | Scientific value |
|---------|----------|----------|-------------------|-----------------|
| **Observe** | "Examine the active site" (zoom + show sticks) | "Proceed" (hide_all + continue) | Yes | Medium (teaches structural awareness) |
| **Quiz** | "What happens next?" (correct → proceed; wrong → teaching text → proceed) | — | Yes (wrong answer still proceeds) | High (reinforces learning) |
| **Explore** | "Look at the cofactors" (show cofactors) | "Look at the substrate" (show substrate) | Yes | Medium |
| **Risk** | "Proceed carefully" (safe) | "Rush ahead" (skip text, maybe miss a detail) | Yes | Low (game-y, not educational) |

**Recommendation for the replan session:** The "Observe" pattern is the best fit —
it uses the PyMOL 3D visualization as gameplay (the player chooses WHAT to look at),
it's still "simple text-based multiple choice" (per spec.md), and it teaches
structural awareness. The "Quiz" pattern is a strong second choice for high-
teaching-value nodes. The specific pattern per node can be a Phase 7 content
decision; the STRUCTURE (add a second choice) can be done in the replan.
