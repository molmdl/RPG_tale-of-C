## Decisions Made
- **edit.prompt is a structural stub, not a playtime node.** It has no is_ending and no cancel/return choice. Its 3 choice.goto edges to the edit-related bad endings exist solely so the BFS sees those endings as reachable (SC2). At runtime, the controller calls engine.apply_player_edit(intent, enzyme_id) which routes via the EditRouter (c14/edit_router.py) — known edits -> defined branch_node, unknown edits -> bad-ending pool — bypassing the stub's choices entirely. The design doc (Plan 05.1-05) must document this: the stub is structural; the EditRouter is the runtime mechanism.
- **Bad-ending pool id parity.** bad.lost_connection + bad.released_from_host match the Phase 4 EditRouter global bad_ending_pool in c14/data/edits.json exactly (["bad.lost_connection", "bad.released_from_host"]). This plan needed ZERO edits.json update — the ids were chosen to match the existing fallback pool.
- **Ending-tier tags for greppability.** Ending nodes carry ending-tier tags (ending:good/normal/bad) mirroring end.true's ending:true tag (etc_atp.json) so the SC5 classification + ending distribution are greppable. edit.prompt carries tags: ["edit:prompt"].
- **bad.cycle_trap_host_death is a visit-count cond gate, NOT an RNG node.** It is reached via tca.shuffle's cond-gated choice (cond: visits.get('tca.shuffle', 0) > 5, authored in Plan 02's tca.json). N=5 is a placeholder game-design parameter (research OQ3, NOT a science claim) — human confirms at Phase 6 playtest.
