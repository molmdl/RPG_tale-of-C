<objective>
Create the bundled-data path-resolution helper (`c14/paths.py`) that derives file locations from `__file__` (not `os.getcwd()`), with a CWD-independence unit test that physically changes into a temp directory to prove resolution still works. Verify (not create) that the existing `README.md` satisfies DOC-04.

Purpose: When the plugin is unzipped into PyMOL's `startup/` dir, the runtime CWD is unpredictable (PyMOL launch dir). CWD-relative paths silently break; `__file__`-relative paths always work. This is Pitfall #1 in the project's research (the #1 breakage mode). Baking the convention into a single helper + test in Phase 1 means every later phase inherits correct path handling. The README already satisfies DOC-04 (verified by 01-RESEARCH-paths.md reading the 57-line file in full) — this is a verification task, not creation.

Output: `c14/paths.py` with `data_path()`/`selfcheck()`, a `c14/data/selfcheck.json` fixture, `tests/test_paths.py`, and a verified README.
</objective>

1. **`c14/paths.py`** — adopt the reference design from 01-RESEARCH-paths.md lines 77-126 near-verbatim. Key requirements:
   - Module docstring explaining: pure-Python (no pymol/PyQt5), unit-testable in WSL, all bundled-data lookups go through `data_path()`.
   - `_PACKAGE_ROOT = Path(__file__).resolve().parent` — the `c14/` directory. `.resolve()` dereferences the repo symlink during dev and makes it absolute.
   - `def data_path(*relative_parts):` → `return _PACKAGE_ROOT.joinpath(*relative_parts)`. Pure resolver — does NOT check existence (separation of concerns; callers open files and handle `FileNotFoundError` naturally; a resolver that raises breaks "compute where a future file would go" use cases). Return type `pathlib.Path`.
   - `def selfcheck():` → `fixture = data_path("data", "selfcheck.json")`; `if not fixture.is_file(): raise FileNotFoundError(...)` with a clear message; `return str(fixture)`. Intended to be called by the test (Phase 1) and by the plugin loader at startup (Phase 6+ — Pitfall 1 mitigation: "fail loud on plugin load").
   - Use f-strings (3.6-safe, PEP 498) or `.format()` — either is fine. No `@dataclass`, no `from __future__ import annotations`, no PEP 604 unions.

2. **`c14/data/selfcheck.json`** — tiny fixture (01-RESEARCH-paths.md line 260-262):
   ```json
   {"purpose": "c14 path-resolution self-check fixture -- do not delete"}
   ```
   This file lives INSIDE the package so it ships in the PyMOL Plugin Manager zip. It is distinct from the repo-root `data/` directory that Plan 03 creates for `data/citations.json`.

3. **`tests/test_paths.py`** — adopt the reference design from 01-RESEARCH-paths.md lines 196-250 near-verbatim. stdlib `unittest`. Key requirements:
   - `class TestPathResolution(unittest.TestCase)` with `setUp`/`tearDown` that save `os.getcwd()`, `tempfile.mkdtemp(prefix="c14_pathtest_")`, `os.chdir(self._tmp)`; tearDown restores CWD + `shutil.rmtree(self._tmp, ignore_errors=True)`. **Running EVERY test from a foreign working directory is the CWD-independence proof** (research Pattern 2: real `os.chdir` > `mock.patch('os.getcwd')` — a real chdir is the honest end-to-end proof).
   - `test_selfcheck_resolves_from_arbitrary_cwd` — call `selfcheck()`, assert the returned path `is_absolute()`, `is_file()`, and `parent` is NOT the temp dir (belt-and-suspenders). If resolution were cwd-relative, the fixture would not be found from the temp dir → `selfcheck()` would raise → test fails. Existence-from-foreign-CWD IS the proof.
   - `test_data_path_returns_absolute_path` — `data_path("data", "selfcheck.json")`, assert `is_absolute()`, assert `resolve().parent == (pkg_root / "data").resolve()` where `pkg_root = Path(__file__).resolve().parent.parent / "c14"`.
   - `test_data_path_does_not_raise_for_nonexistent_file` — `data_path("data", "does-not-exist-yet.json")`, assert `is_absolute()` and `not exists()`. Proves the resolver is pure (no existence coupling).

**Important**: The test imports `from c14.paths import data_path, selfcheck`. This runs `c14/__init__.py` first — which is why Plan 01's `c14/__init__.py` must be pymol/PyQt5-free (it is). If the import fails with a Qt/display error, that means Plan 01's `__init__.py` has a pymol import (it shouldn't).

Run: `python3.6 -m unittest discover -s tests -v` from repo root. This now runs BOTH `test_imports.py` (Plan 01) and `test_paths.py` (this plan) — both must pass.
