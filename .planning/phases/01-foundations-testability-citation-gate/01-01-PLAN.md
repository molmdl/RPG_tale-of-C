  <action>
Create the AST-based import-boundary gate and its test suite. Python 3.6 stdlib ONLY. Use the reference design in 01-RESEARCH-testability.md "Code Examples" (verified empirically on 3.6.9: catches all 7 static violation forms, 0 false positives on comments/strings, correct dir-exclusion).

1. **`tools/check_imports.py`** — adopt the verified reference design from 01-RESEARCH-testability.md lines 233-311 near-verbatim. Key requirements:
   - Walk `c14/` with `os.walk`, PRUNING `{"pymol_layer", "ui", "__pycache__"}` in-place (dirnames[:] assignment).
   - `ROOT = os.path.join(os.path.dirname(os.path.dirname(os.path.abspath(__file__))), "c14")` — resolves to repo-root `c14/` regardless of CWD.
   - `BANNED_TOP = ("pymol", "PyQt5")`. `_banned(module_name)` splits on "." and checks the top-level package.
   - `violations_in(path, rel)` — `ast.parse` the file (catch SyntaxError → report as a violation so py_compile failures surface here too), walk `ast.Import` (check each `alias.name`) and `ast.ImportFrom` (check `node.module`), append `"file:line import X"` / `"file:line from X import Y"` strings. Also do a secondary line-scan for dynamic imports (`__import__`/`import_module` mentioning pymol/pyqt5) → append `"file:line REVIEW dynamic import: ..."`.
   - `main()` walks the tree, collects violations, prints to stderr + returns 1 if any, else prints "check_imports: clean ..." + returns 0.
   - **STRICT-BAN policy** (research Open Question 1, recommendation: BAN): the gate flags ANY `pymol`/`PyQt5` Import/ImportFrom node, INCLUDING those inside `if TYPE_CHECKING:` guards. Do NOT add TYPE_CHECKING-awareness. The architecture (MolAction = pure data) means domain never needs to name a pymol type. If a future phase genuinely needs type-cross-references, reconsider then.
   - Shebang `#!/usr/bin/env python3.6`. Module docstring explaining the gate.
   - `if __name__ == "__main__": sys.exit(main())`.

2. **`tests/test_imports.py`** — stdlib `unittest`. Four test methods:
   - **`test_violations_in_catches_banned_imports`** — call `violations_in()` on a temp file (or in-memory via `ast.parse` + walk) containing each banned form: `import pymol`, `from pymol import cmd`, `import pymol.cmd as c`, `from pymol.Qt import QtWidgets`, `from pymol.cgo import CGO`, `import PyQt5.QtCore`, `from PyQt5 import QtWidgets as W`. Assert each produces ≥1 violation. (Use `tempfile.NamedTemporaryFile` with suffix `.py` write-then-read, OR refactor `violations_in` to accept source string — preferred: write a tiny helper that calls `ast.parse` + the same walk logic. Simplest: write temp .py files to a tempdir and call `violations_in(path, rel)`.)
   - **`test_violations_in_no_false_positives`** — a source file where `pymol`/`PyQt5` appear ONLY in comments (`# import pymol here`) and string literals (`"from pymol import cmd"`), plus a real allowed import (`import json`). Assert `violations_in()` returns `[]` (zero violations). This proves AST > grep.
   - **`test_gate_passes_on_clean_skeleton`** — `subprocess.run([sys.executable, "tools/check_imports.py"], capture_output=True)` from repo root. Assert `returncode == 0` and stdout contains "clean". (The skeleton from Task 1 has no domain-tier pymol imports.)
   - **`test_py_compile_all_domain_modules`** — walk `c14/` (pruning `pymol_layer`, `ui`, `__pycache__`), `py_compile.compile(each_file, doraise=True)` for each `.py`. Assert no exception. This explicitly satisfies success-criterion #1's "pass `python3.6 -m py_compile`" requirement AND pairs it with the import check (research Pitfall 3: py_compile is necessary but not sufficient — PEP 604 `int | None` compiles but raises at import; the unittest run in Plans 02/03 does the import half).

Use `os.path.join(os.path.dirname(os.path.abspath(__file__)), "..")` to locate repo root from the test file (so the test runs regardless of CWD). Use `subprocess.run([sys.executable, ...])` not hardcoded `python3.6` (so it uses the same interpreter running the test).

The AST gate proves no banned imports; the unittest run imports all domain modules (proving import-cleanliness beyond py_compile). Together they satisfy success-criterion #1 fully.
