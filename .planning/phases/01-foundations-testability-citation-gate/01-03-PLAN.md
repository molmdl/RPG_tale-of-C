<objective>
Create the citation registry loader (`c14/citations.py`), the pre-ship gate (`tools/check_citations.py`), fixture data demonstrating both pass and fail paths, and the test suite. Together these enforce spec.md's no-fabricated-science rule architecturally: no story node can ship referencing a missing or unapproved claim.

Purpose: This is the architectural enforcement of the project's strongest constraint. A JSON registry (`data/citations.json`) maps each `claim_id` to its source + `approval_status`; the gate cross-references story nodes' `claim_ids` against the registry and exits non-zero on any missing/non-approved claim. The registry is a repo-root content file (NOT bundled in the plugin zip — distinct from `c14/data/`), read at pre-ship time by the gate. Phase 1 demonstrates the gate works both ways (pass + fail) using clearly-placeholder fixture data; real claims land in Phase 5+.

Output: `c14/citations.py`, `data/citations.json` (stub), `data/citations.README.md`, `tools/check_citations.py`, 6 fixture files, `tests/test_citations.py`.
</objective>

   - `__init__(self, data)` — stores the dict (`self._claims = data`).
   - `@classmethod load(cls, path)` — opens the file, `json.load(f, object_pairs_hook=_no_duplicate_keys)` where `_no_duplicate_keys(pairs)` is a module-level function that raises `ValueError("duplicate claim_id in registry: {!r}".format(k))` on a duplicate key (research Pitfall 3 — verified working on 3.6.9).    - `contains(self, claim_id)` — `return claim_id in self._claims`.
