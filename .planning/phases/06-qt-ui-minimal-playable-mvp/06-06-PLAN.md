`Controller` class:
- `__init__(self, story_dir, molops, cmd, edit_router, view=None, prompt_fn=None, count_fn=None, achievement_board=None, view_provider=None, view_applier=None)`:
  - `self._graph = StoryGraph.load(story_dir)` (story_dir is a path string — DI; plugin_entry passes `str(data_path("data","story_glucose"))`, tests pass the repo-root path).
  - Store molops, cmd, view, prompt_fn, achievement_board.
  - `self._count_fn = count_fn or (lambda sele: cmd.count_atoms(sele))`.
  - `self._hero_resolver = HeroResolver(self._count_fn, self._prompt_fn) if prompt_fn is not None else None`.
  - `self._engine = GameEngine(self._graph, molaction_sink=self._dispatch_molaction, edit_router=edit_router, view_provider=view_provider, view_applier=view_applier)`.
  - `self._pending_on_enter = None` (the HeroResolver rewrite stash).
- `_dispatch_molaction(self, action)` — if `self._pending_on_enter is not None`: drain the pending list (forward each to `self._molops.apply`), then clear it; ELSE forward `self._molops.apply(action)` directly. This is the testability seam: the engine calls this per-action (engine.py:187-189); the controller forwards to molops OR drains the HeroResolver-rewritten sequence. (Simplest robust impl: the HeroResolver monkey-patches the target node's `on_enter` list in-place before engine.choose via a save/restore — see _resolve_hero_for_target; then _dispatch_molaction just forwards to molops.apply. Pick the monkey-patch+restore approach: save the original on_enter, swap in resolved, call engine.choose/goto, restore in finally. This avoids the pending-queue complexity.)
- `start_game(self, character="glucose", seed=None)` — `turn = self._engine.start(character, seed)`; `self._record_achievement(turn, character, is_new_game=True)`; `self._render(turn)`.
- `choose(self, index)` — resolve hero for the target node FIRST (see _resolve_hero_for_target), then `turn = self._engine.choose(index)`; `self._record_achievement(turn, self._engine.state.character)`; `self._render(turn)`.
- `take_choice(self, choice)` — the tca.shuffle routing: for a NON-weighted choice at a mixed node, the UI calls this (NOT choose). Resolve hero for choice.goto, then `turn = self._engine.goto(choice.goto)`; record + render. (Used for edit:offer -> edit.prompt + cycle-trap -> bad.cycle_trap_host_death.)
- `apply_edit(self, edit_intent)` — `enzyme_id = self._current_enzyme_id()`; if None raise RuntimeError; `turn = self._engine.apply_player_edit(edit_intent, enzyme_id)`; record + render.
- `build_edit_intent(self, op, target, args)` — `enzyme_id = self._current_enzyme_id()`; if None raise; return `EditIntent(op, target, args, enzyme_id)` (the edit dialog collects op/target/args from curated options; the controller assembles the EditIntent whose signature() must match edits.json).
- `save(self, path)` / `load(self, path)` — `self._engine.save(path)` / `turn = self._engine.load(path)` + render.
- `_current_enzyme_id(self)` — `node = self._engine.graph.get_node(self._engine.state.current_node)`; `return next((t.split(":", 2)[2] for t in node.tags if t.startswith("edit:enzyme:")), None)` (05.1-DESIGN.md:619-623).
- `_record_achievement(self, turn, character, is_new_game=False)` — if `self._achievement_board is not None`: `self._achievement_board.on_turn(turn, character, is_new_game)`.
- `_render(self, turn)` — if `self._view is not None`: `self._view.render_turn(turn)`.
- `_resolve_hero_for_target(self, target_node_id)` — if `self._hero_resolver is None or target_node_id is None: return`; `target = self._engine.graph.get_node(target_node_id)`; `original = target.on_enter`; `resolved = self._hero_resolver.resolve(original)`; `target.on_enter = resolved`; (restore after dispatch — use a try/finally around the engine.choose/goto call in choose()/take_choice(): `target.on_enter = original` in finally). This is the monkey-patch+restore approach (06-RESEARCH-ui-adapter.md Open Question 2 recommended: one-shot mutate + restore is safe; the engine re-reads node.on_enter each _enter).
- A helper `is_mixed_weighted_node(self, node)` — return True if node has >=1 weighted choice AND >=1 non-weighted eligible choice (the tca.shuffle case; used by the view to decide the UI rendering — Spin button + separate Edit/conditional buttons vs one-button-per-choice). Delegates cond check to `self._engine.choice_cond_met(choice)`.

`HeroResolver` class (06-RESEARCH-ui-adapter.md Pattern 3):
- `__init__(self, count_fn, prompt_fn)` — store count_fn (sele -> int), prompt_fn (message -> bool).
- `resolve(self, on_enter_actions)` — detect a hero-highlight sequence (a `label` op with text "YOU" — the OQ-4 frozen hero marker); for it, `hero_sele = action.args.get("sele", action.target)`; `n = self._count_fn(hero_sele)`; if `n == 1`: return on_enter_actions unchanged (single-C, deterministic, no prompt); if `n != 1` (multi-C ambiguous): `default_sele = "{0} and elem C".format(action.target)` (first carbon; a robust default); `confirmed = self._prompt_fn("This structure has {0} carbons. The hero (C14) is ambiguous. Highlight the first carbon as the hero?".format(n))`; if confirmed: return a NEW list with the hero ops' `sele` rewritten to default_sele (copy the MolActions with updated args); else return unchanged. If no "YOU" label in on_enter: return unchanged (no hero-highlight, no-op). Return a COPY (do not mutate the input list — the controller's restore relies on the original being intact; actually the controller saves `original = target.on_enter` BEFORE calling resolve, so resolve CAN return a new list).
- The rewrite: build a new list; for each action, if it's a hero op (op in {show_as, color, show, set, label} targeting the hero object), replace its `sele`/`target` args with default_sele where applicable. Keep it simple: rewrite the `label` + `show spheres` + `set sphere_scale` ops' `sele` to default_sele; the `show_as sticks` + `color` ops keep the object-wide sele (they apply to the whole object by design). Document this.

AVOID: do NOT import pymol or PyQt5 in controller.py (the testability boundary — 06-RESEARCH-ui-adapter.md Pitfall 1+6; `python3.6 -c "import c14.ui.controller"` must succeed in pure WSL with no pymol). do NOT put the OQ-6 prompt inside molops (molops stays pure). do NOT call cmd.* from the controller EXCEPT via the injected count_fn (which wraps cmd.count_atoms) — the controller itself never imports cmd. do NOT hardcode the story path (DI via story_dir). do NOT use @dataclass (3.6).
