```python
"""Qt plugin entry point -- called by c14/__init__.py.__init_plugin__.

Gate-exempt: may import pymol.Qt / pymol.plugins
(tools/check_imports.py SKIP_DIRS = {"pymol_layer", "ui", "__pycache__"}).
Defer pymol imports to INSIDE init_plugin / _open_main_window so merely
importing c14/__init__.py (during PyMOL's __import__ phase) does NOT touch
Qt before the GUI is ready. Matches dynoplot.py:445-447 + optimize.py:29-31.
"""
_main_window = None  # singleton; constructed lazily on first menu click


def init_plugin(pmgapp):
    # type: (object) -> None
    """Register the 'RPG: Tale of C' menu item. Called once on plugin load."""
    from pymol.plugins import addmenuitemqt            # plugins/__init__.py:100
    addmenuitemqt('RPG: Tale of C', _open_main_window)  # label, no-arg callback


def _open_main_window():
    """Menu callback: construct (or re-show) the main game window."""
    global _main_window
    from pymol.Qt import QtWidgets                     # Qt is ready at click time
    from .main_window import MainWindow                # c14/ui/main_window.py (06-08)
    if _main_window is None:
        _main_window = MainWindow()
    _main_window.show()
    _main_window.raise_()
```

The `_open_main_window` lazy import of `MainWindow` is deferred to click time — so this file py_compiles even if `c14/ui/main_window.py` does not exist yet (the import is inside the function). The `MainWindow` class (06-08) constructs the molops stack + Controller + the widgets.

AVOID: do NOT eagerly construct the MainWindow inside init_plugin (slows every PyMOL startup + builds widgets before the user asks — 06-RESEARCH-qt-packaging.md Anti-Pattern). do NOT import pymol at module top (defer to inside the functions, matching dynoplot.py). do NOT pass pmgapp through to MainWindow (modern Qt plugins ignore it; use `from pymol.gui import get_qtwindow` if a parent is needed — 06-RESEARCH-qt-packaging.md Open Question 1). do NOT use the legacy `__init__(pmgapp)` name (PLGN-01 mandates `__init_plugin__`).
