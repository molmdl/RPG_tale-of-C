## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed the `gray80` color-name round-trip (get_color_indices `all` parameter)**

- **Found during:** Task 2 (headless run — 2 stages failed: `case2_dim_gray80` + `climax_co2_faded`)
- **Issue:** The `color_name_for()` helper called `cmd.get_color_indices()` with the default `all=0`, which returns only 178 "user-facing" colors and OMITS standard extended colors like `gray80` (the scoped-dim + the CO2-fade color). `gray80`'s index (4236) only appears with `all=1` (5388 colors). The custom `hero_gold` happened to be in `all=0` (so Cases 1/3 passed), but `gray80` returned `None` (so the dim + fade checks failed). This is a smoke-mechanics bug, NOT a convention impact (the convention specifies `gray80` as the dim color; the smoke's verification primitive was too narrow).
- **Fix:** Changed `cmd.get_color_indices()` → `cmd.get_color_indices(all=1)` in both the `color_name_for()` helper and the Stage 0 `hero_gold_defined` check. `all=1` is a strict superset of `all=0`, so all named colors (custom hero_gold + standard gray80/gray/green/red/orange) round-trip correctly.
- **Files modified:** tools/hero_highlight_smoke.py (2 call sites)
- **Verification:** Re-ran `bash tools/run_headless.sh tools/hero_highlight_smoke.py` → `PASSED` with all 25 stage checks green (including `case2_dim_gray80 dim-color='gray80'` + `climax_co2_faded co2-faded-color='gray80'`).
- **Committed in:** d38ab80 (Task 2 commit)
