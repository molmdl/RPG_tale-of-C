**Researched:** 2026-09-04
**Domain:** Self-contained offline HTML editor for story-node JSON (vanilla JS + SVG, zero dependencies, no servers)
**Confidence:** HIGH (repo facts all read from git-committed sources; web facts from MDN + caniuse static data fetched today)

## Summary

Three questions drove this research: (1) what exists in-repo to reuse, (2) how should a dependency-free offline HTML **editor** be architected, and (3) how does an offline `file://` HTML page **save files**. All three have concrete answers grounded in the committed repo.

**(1) Prior art.** The committed `tools/story_graph_viewer.py` (git `HEAD`, 837 lines) provides the complete, proven **data layer**: loaders (`load_story` :123, `load_registry` :164, `load_cast` :173, `load_edits` :190), derivations (`derive_kind` :206, `effects_summary` :236, `summarize_on_enter` :254), model build (`build_model` :319, `_build_solid_edges` :494, `_build_dashed_edges` :569, `_compute_review_order` :594), and an integrity self-check (`check_integrity` :620, 10 numbered gates, `VIEWER_FAIL` + exit 1). **CRITICAL finding:** the committed file contains **NO `render_html()` and writes NO HTML** — the docstring (:2–27) describes HTML emission, but `main()` (:788–833) only builds the model, gates, prints stats, and optionally dumps the payload JSON. The HTML emission (template + inline SVG + data island, emitted 248,515 bytes to `dist/story_graph_viewer.html`) exists only in the **uncommitted working copy** (+1,066 lines, `render_html` at :1036) owned by a concurrent agent. Plans must treat the committed model/integrity layer as the reusable substrate and write fresh JS/SVG; the uncommitted JS may be *consulted* but must not be depended on.

**(2) Architecture.** Same generator pattern as the viewer: one Python 3.6 stdlib file (`tools/story_editor.py`) that loads the 5 data targets, runs integrity gates, and emits one self-contained HTML (`tools/story_editor.html`, committed) with all data inlined as a JSON data island (`ensure_ascii=True`, `</` → `<\/`) and a classic (non-module) inline script. Editor state = one in-memory "edited bundle" object; every mutation goes through a mutator that pushes a deep-clone snapshot onto an undo stack (57 nodes ≈ 92 KB raw → snapshots are trivially cheap), debounced localStorage autosave as crash insurance, and explicit draft/save-edit actions.

**(3) Persistence (the pivotal answer).** As of 2026-09 (caniuse static data fetched today): **File System Access API (`showOpenFilePicker`/`showSaveFilePicker`) is Chrome 105+/Edge 105+/Opera 91+ only; Firefox (through 157) and Safari (through 27) never shipped it** (Mozilla position: "harmful"). It is secure-context-gated, but **`file://` URLs are "generally potentially trustworthy"** (MDN Secure Contexts, 2026-08-15), so a local file page in Chrome/Edge can use the pickers. `requestPermission()` requires transient user activation and reverts to `'prompt'` across page loads, so re-permission prompts are a normal part of the flow. Recommended hybrid: **FSA-first for both draft (write `tmp/…draft.json`, git-ignored) and save-edit (write the real JSON in place), with a Blob-download fallback** for non-Chromium browsers; **localStorage is only an opportunistic crash-recovery layer behind the MDN `storageAvailable()` try/catch** — it must never be the primary draft store because `file://` localStorage behavior is per-browser and partly unverifiable (opaque-origin `SecurityError` risk per the HTML spec).

**Primary recommendation:** One generator (`tools/story_editor.py` → committed `tools/story_editor.html`), snapshot-stack undo, FSA-first persistence with download fallback, paste-in scene capture validated against the known MolAction op set, and Python-side tests treating the emitted HTML as data (sentinels + data-island parse + placeholder-leak scan); all GUI behavior = human-verify checkpoints.

### Generator architecture (mirror the viewer's committed shape)

#   build_model() -> check_integrity() -> render_html(); EDITOR_FAIL + exit 1 on gate violations.

### Recommended in-browser editor architecture (vanilla JS)

```
┌─────────────────────────────────────────────────────────────────────┐
│ data island:  <script id="editor-data" type="application/json">      │
│   { bundle: {manifest, files:{fname:{nodes}}, edits_doc, cast_doc,   │
│     citations, sources}, meta:{generated_at, invariants} }           │
├─────────────────────────────────────────────────────────────────────┤
│ STATE  = { bundle, dirty:set<fname>, undo:[], redo:[], sel:id }      │
│ MUTATE = every change flows through mutators:                        │
│   function apply(action){ snapshot(); action.redo(STATE.bundle);     │
│     STATE.dirty.add(action.file); scheduleDraftSave(); rerender(); } │
│ VIEWS  = SVG graph (left, zoom/pan) + node form panel (right) +      │
│          path-trace panel + claims panel (C)                         │
│ PERSIST= FSA-first (pickers, session handle cache, in-place write)   │
│          + download fallback + debounced localStorage crash copy     │
└─────────────────────────────────────────────────────────────────────┘
```

Key structural choices:

1. **Edit the raw bundle, not the derived model.** Keep `files[fname].nodes[id]` as the source of truth (ordered objects — Python 3.6 dict order is preserved by `json.dumps` and JS object key order for string keys); re-derive the display model (kinds/edges/positions) after each mutation. This mirrors the viewer's load→derive split and guarantees round-trip fidelity. **Preserve unknown keys** (extensibility B11): mutators touch only known fields; never rebuild nodes from a fixed field whitelist.
2. **Event delegation** on containers (graph SVG + panel lists) — one `click`/`input` listener per container, dispatch on `data-*` attributes. No per-row listeners (57 nodes × N choices × form fields adds up and breaks on re-render).
3. **Rerender strategy:** full rerender of the SVG + panel per mutation is fine at this scale (57 nodes; the working-copy viewer already does full-rerender SVG at 248 KB emitted). Keep zoom/pan transform in view state that survives rerender.
4. **Selection-driven editing:** click node → form panel shows every editable aspect (B2 type via `is_ending` + tags; B3/B4/B5 choice list with goto/weight/cond/effects/tags; B6 texts; B7 cast linkage; B8 on_enter list; B10 pool membership). This covers B1–B10 with ONE interaction model (form panel), keeping graph interactions minimal (below).

### Persistence — recommendation with tradeoffs (the pivotal question)

| Option | Offline | Writes real JSON in place | Browsers (Sep 2026, caniuse) | Human friction | Verdict |
|---|---|---|---|---|---|
| **(a) File System Access API** `showOpenFilePicker`/`showSaveFilePicker` + `createWritable()`; `handle.requestPermission({mode:'readwrite'})` on reuse | ✅ (no network involved; secure-context OK since `file://` is "generally potentially trustworthy" — MDN) | ✅ **Yes — the actual repo files** | **Chrome 105–154 ✅, Edge 105–151 ✅, Opera 91+ ✅; Firefox ❌ (never, position "harmful"); Safari ❌ (never, through 27)** | Pick once per file per session; re-permission prompt after each reload; each save = 1 click | **PRIMARY for save-edit + draft** (user is on Windows: Edge ships with Windows; Chrome likely present) |
| **(b) Blob download** (`URL.createObjectURL` + `<a download>`) | ✅ works everywhere, every browser | ❌ no — lands in Downloads; human moves files over originals | all | Multi-file edits → multiple downloads (Chrome asks "allow multiple downloads" once); human must copy files into `data/`/`rpg/data/` | **FALLBACK** (auto-detect: `if (!window.showSaveFilePicker)`) |
| **(c) localStorage draft** | ✅ | ❌ browser-profile storage, not files | **per-browser on `file://` — NOT guaranteed** (see Pitfall 1) | zero | **Crash-recovery ONLY**, behind MDN `storageAvailable()` try/catch; never the primary draft (ROADMAP E explicitly wants a *tmp file*) |
| **(d) Patch-file + Python applier** (editor emits one `story_edits.json`; `tools/apply_story_edits.py` applies + re-runs integrity) | ✅ | ✅ (applier writes) | all | Extra CLI step each save; single download instead of N | **Defer (non-MVP).** Attractive because the applier can re-run `check_integrity` before touching data — note as future hardening, not required by E |

**Recommended hybrid (least friction satisfying E):**
- **Save edit** (writes real JSON): if `window.showSaveFilePicker` exists → per-file FSA flow: for each *dirty* file, `showSaveFilePicker({suggestedName, startIn})` (first time), cache the `FileSystemFileHandle` in session memory, `createWritable()` → write pretty-printed JSON (`JSON.stringify(x, null, 2)` to match repo style) → `close()`. Subsequent saves of the same file reuse the handle after `queryPermission`/`requestPermission`. If FSA absent → download each dirty file; instruct the human where it goes (`data/story_glucose/…` vs `rpg/data/…` — the filename tells them).
- **Save draft** (tmp file, unproven edits): same mechanism targeting `tmp/story_editor_draft.json`; plus **debounced (≈1 s after last mutation) localStorage autosave** as invisible crash insurance, restored via a banner ("draft from earlier session found — restore?") when `storageAvailable('localStorage')` and the draft differs from the island data. localStorage failure is caught and ignored silently.
- **No servers, no POST, no dev-server** (A forbids) — this is why FSA/download are the only real write paths.

### Undo/redo (E)

- **Snapshot stack, not diffs.** One undo entry = full deep-clone of the edited bundle (`JSON.parse(JSON.stringify(bundle))`). At 57 nodes / 92 KB raw this is microseconds and megabytes at worst; a 200-entry cap bounds memory. Diff-based (JSON-patch) or per-field history buys nothing at this scale and is the classic source of subtle undo bugs.
- **Granularity = one logical action** (add node, delete choice, paste on_enter, edit one field commit). Text inputs commit their snapshot on `change` (blur) — not per keystroke — so typing "aconitase" is one undo step. New action clears the redo tail. Undo/redo also flip the file's dirty bit and re-run validation badges.
- **Draft autosave cadence:** debounced 500–1000 ms after the last mutation (not every keystroke, not on a timer while idle). Explicit "Save draft" button forces an immediate FSA tmp write.

### Graph editing UX — minimal interaction set covering B1/B2/B5

The data has **no layout fields** — positions derive from column (file) / row (manifest order) exactly as in the viewer (:60–85, :329–349). Therefore:

- **Connections + direction (B5) = editing `choice.goto`.** An edge's direction is inherent (src → dst). The primary interaction is a **dropdown of existing node ids** on each choice row (grouped by file), with typeahead — click-source-click-target or drag-from-port wiring is nice-to-have but NOT needed; the goto dropdown is unambiguous, keyboard-accessible, and cannot create invisible state.
- **Add node (B1/B2):** "＋ node" button scoped to a file/segment → panel form: id (validated: unique, dot-convention `<seg>.<name>` like `gly.pfk`), initial type (starting/choices/mutation/ending → seeds `is_ending` + tags), then the normal form. Add appends to `files[fname].nodes` (row order = insertion order, mirroring the viewer's layout derivation).
- **Delete node (B1):** blocked-with-explanations if any `choice.goto`, `edits.json` bucket, `branch_node`, `cast.json` id, `manifest.start`, or `bad_ending_pool` member references it; offer "re-point N incoming edges" action. This is the JS mirror of integrity gates 5a/5b/5c (viewer :655–676).
- **Type editing (B2):** `is_ending` select (none/true/good/normal/bad) + tag checkboxes for the meaningful tags (`edit:enzyme:*`, `rng:weighted`, `stage:*`).
- **RNG weights (B10-adjacent):** weight/cond fields exposed on choice rows only when `rng:weighted` tag present.
- **Graph gestures:** zoom/pan/drag-pan as in the viewer (view-only transforms); **node drag = optional view state only** (never persisted — the data has no x/y).
- **Bad-ending pool (B10):** a small editor for `edits.json.bad_ending_pool` (add/remove by node id, list view with tier badges).

### Path tracing (D) — fresh, simple DFS

The viewer's `review_order` (:594–613) is a pinned *linear review sequence*, not a path tracer — the editor needs its own DFS. Sketch: pick a start node (default `manifest.start`); DFS following each choice's `goto`; emit nested `<ul><li>` where each node row shows id, tier/kind chip, choice label; guard cycles with a visited set (render a ↩ marker instead of recursing); expand/collapse per branch; "copy as text" button. Depth is bounded (57 nodes). No cycles exist in the current data (restored nodes have 0 incoming, gate 9), but the guard is still required once editors can create arbitrary edges.

### Reference/source checking (C)

Read-only panels over the two registries: claim chips on nodes (the viewer already renders `claim_ids` per node) → click opens the claim record (`claim_text`, `review_tier`, `approval_status`) → `source_id` links to the `sources.json` record (`url`, `license`, approval). Show a per-node warning chip when any `claim_id` is unapproved or unresolved (mirror of gate 6a, viewer :679–697). **The editor must NOT write `citations.json`/`sources.json`** — approvals are human-gated by policy (spec.md non-negotiables); C is read-and-jump, not edit.

### Anti-patterns to avoid

- **Do not** `fetch()` sibling JSON files — `file://` fetch is CORS-blocked in Chromium; everything must ride the data island (the viewer already inlines for this reason).
- **Do not** use `<script type="module">` or ES-module imports — module scripts fail under `file://` CORS; use one classic inline script.
- **Do not** persist layout coordinates into the story JSON (no such schema; the engine/gates don't know them).
- **Do not** rebuild nodes with a fixed whitelist of fields — unknown keys must round-trip (B11 extensibility + engine tolerance).
- **Do not** modify `tools/story_graph_viewer.py` or `.gitignore` (concurrent agent owns both; both have uncommitted changes right now).

## Common Pitfalls

### Pitfall 1: localStorage on `file://` is NOT portable
**What goes wrong:** Draft autosave silently fails (or silently shares across ALL local files) depending on browser.
**Why:** Storage is strictly per-origin (MDN Web Storage, 2026-05-26); the HTML spec throws `SecurityError` on storage access from an opaque origin; browsers disagree on whether a `file://` document is opaque. Chrome's behavior (works, shared `file://` origin) and Firefox/Safari behavior are per-browser details I could not re-verify from a fetched source today — treat as **LOW confidence** per browser.
**How to avoid:** (1) Primary draft = a real tmp file (FSA or download) per ROADMAP E; (2) localStorage only as guarded crash-recovery via the MDN `storageAvailable()` try/catch, wrapped so any throw is swallowed; (3) never store the only copy of work there.
**Warning signs:** "Save draft" works in the dev browser but throws SecurityError in another.

### Pitfall 2: FSA re-permission + picker fatigue
**What goes wrong:** Every page reload reverts handle permission to `'prompt'`; saving 9 files = 9 pickers; users perceive data loss when a save silently aborts.
**Why:** MDN: `requestPermission()` requires transient user activation; permission state is granted/denied/prompt and is not durable across reloads for ordinary (non-installed) pages; `showSaveFilePicker` throws `AbortError` when the user cancels.
**How to avoid:** Cache handles in session memory; on save loop, `queryPermission` → `requestPermission` → write; catch `AbortError` and report "skipped <file>" instead of crashing; save only *dirty* files (usually 1); surface a dirty-files list before the picker loop so the human knows what's coming.
**Warning signs:** Unhandled promise rejections on cancel; picks landing in the wrong directory (use `startIn` + `id` options for memory).

### Pitfall 3: Multi-file save UX
**What goes wrong:** One logical edit can dirty up to 9 files (7 story + `rpg/data/edits.json` + `rpg/data/cast.json`); download fallback produces a Downloads-folder full of JSONs the human must place by hand — misplacement silently corrupts the bundle layout.
**How to avoid:** Track dirty **per file** and display the filename + its repo-relative destination on every save affordance ("glucose/tca.json → data/story_glucose/tca.json"); on the download fallback, prefix filenames with their subpath (`data_story_glucose__tca.json`) only if needed — prefer keeping original names + a visible path label. Post-save, remind the human to run the repo gates (`python3.6 tools/story_graph_viewer.py`, the suite) — the editor's JS warnings are advisory, the Python gates are authoritative.

### Pitfall 4: Emitted-HTML hazards (data island + script breakout)
**What goes wrong:** Story text contains `</script>` (breaks out of the data island) or non-7-bit characters (encoding surprises); `.format()` on the template explodes on JS braces; `<script type="module">` fails on `file://`.
**Why/how to avoid:** The working-copy viewer already solved these — `json.dumps(..., ensure_ascii=True)` + `.replace("</", "<\\/")` on the payload, template substitution via `str.replace` tokens only, one classic inline script. Copy that discipline. Also escape `__TOKEN__`-shaped text in user content? Not needed — tokens appear only in the template, data rides the island.
**Warning signs:** Generator tests should assert zero `__UPPERCASE__` token leaks and that the island parses back to the exact model.

### Pitfall 5: Committed `dist/` assumption
**What goes wrong:** Editor HTML emitted to `dist/` (viewer's default) is **git-ignored** — the "committed artifact" decision silently fails.
**Why:** Committed `.gitignore` explicitly ignores `dist/` ("Build output … NOT committed").
**How to avoid:** Default the editor's `--output-dir` to `tools/` (artifact committed next to its generator); keep `--output-dir` overridable. **Never** edit `.gitignore` (concurrent agent owns it).

### Pitfall 6: Verification gaps for JS-heavy artifacts from WSL
**What goes wrong:** No node/npm guaranteed, no headless browser guaranteed — a JS syntax error ships undetected and the editor is a white screen.
**How to avoid:** Automate everything expressible in Python (next section); treat any runtime JS behavior as **human-verify in a real browser** (same split the repo already uses for Qt: automated headless checks + human GUI pass). A cheap extra net: keep the JS in a few large, plain functions and avoid clever syntax; ES2017-level features only (async/await is fine in Chrome/Edge/Firefox/Safari today).
**Warning signs:** Generator smoke can only prove structure, not behavior — plan a browser checkpoint task explicitly.

### Pitfall 7: Concurrent-agent collision
**What goes wrong:** Plans that touch `tools/story_graph_viewer.py` or `.gitignore`, or that copy from the viewer's *uncommitted* JS.
**Why:** Both files are modified-uncommitted by another agent right now (`git status`: `M .gitignore`, `M tools/story_graph_viewer.py`).
**How to avoid:** Read the committed versions (`git show HEAD:…`); duplicate needed helpers into `tools/story_editor.py` rather than importing from the viewer; never import viewer modules (its `main` also gates on pinned counts that Phase 8 will legitimately change).

### 2. Snapshot undo core

```js
// Standard pattern; scale-safe for 57 nodes (~92 KB raw bundle)
var undoStack = [], redoStack = [], MAX_UNDO = 200;
function snapshot() {
  undoStack.push(JSON.stringify(STATE.bundle));     // serialize = deep clone
  if (undoStack.length > MAX_UNDO) undoStack.shift();
  redoStack.length = 0;
}
function undo() { if (!undoStack.length) return;
  redoStack.push(JSON.stringify(STATE.bundle));
  STATE.bundle = JSON.parse(undoStack.pop()); rerender(); }
function redo() { if (!redoStack.length) return;
  undoStack.push(JSON.stringify(STATE.bundle));
  STATE.bundle = JSON.parse(redoStack.pop()); rerender(); }
```

function parseScenePaste(text) {   // committed contract: scene_capture.py:416-434
  var lines = text.split(/\r?\n/).filter(function (l) {
    var s = l.trim(); return s !== "" && !s.startsWith("//") && !s.startsWith("#"); });
  var body = lines.join("\n");
  var a = body.indexOf("["), b = body.lastIndexOf("]");
  if (a < 0 || b < 0) throw new Error("no JSON array found in paste");
  var ops = JSON.parse(body.slice(a, b + 1));
  var KNOWN = ["set_color","show_as","color","show","label","select_focus","zoom",
               "set_view","set","edit","align","load","hide_all"];
