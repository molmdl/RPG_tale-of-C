## Summary

Three questions drove this research: (1) what exists in-repo to reuse, (2) how should a dependency-free offline HTML **editor** be architected, and (3) how does an offline `file://` HTML page **save files**. All three have concrete answers grounded in the committed repo.

**(1) Prior art.** The committed `tools/story_graph_viewer.py` (git `HEAD`, 837 lines) provides the complete, proven **data layer**: loaders (`load_story` :123, `load_registry` :164, `load_cast` :173, `load_edits` :190), derivations (`derive_kind` :206, `effects_summary` :236, `summarize_on_enter` :254), model build (`build_model` :319, `_build_solid_edges` :494, `_build_dashed_edges` :569, `_compute_review_order` :594), and an integrity self-check (`check_integrity` :620, 10 numbered gates, `VIEWER_FAIL` + exit 1). **CRITICAL finding:** the committed file contains **NO `render_html()` and writes NO HTML** — the docstring (:2–27) describes HTML emission, but `main()` (:788–833) only builds the model, gates, prints stats, and optionally dumps the payload JSON. The HTML emission (template + inline SVG + data island, emitted 248,515 bytes to `dist/story_graph_viewer.html`) exists only in the **uncommitted working copy** (+1,066 lines, `render_html` at :1036) owned by a concurrent agent. Plans must treat the committed model/integrity layer as the reusable substrate and write fresh JS/SVG; the uncommitted JS may be *consulted* but must not be depended on.

> **Amendment note (2026-09-04, later the same day):** while re-verifying browser behavior for the persistence rewrite below, the concurrent agent's viewer commit landed: `85a1711` (2026-09-04) commits the viewer's HTML emission (`render_html` now at HEAD :1044, `OUTPUT_NAME` :44; clean worktree). The "UNCOMMITTED working copy" caveat in this paragraph and all pre-`85a1711` line numbers used in this document are therefore historical — re-derive exact line numbers from HEAD when implementing. The ownership rule is unchanged: `tools/story_graph_viewer.py` and `.gitignore` remain off-limits to Phase 7.1; its JS is prior art to consult, not import.

**(2) Architecture.** Same generator pattern as the viewer: one Python 3.6 stdlib file (`tools/story_editor.py`) that loads the 5 data targets and runs the integrity gates as a **generation-time sanity check over the live repo data** (nothing is embedded), then emits one self-contained HTML **shell** to the **repo root** (`story_editor.html`, committed). Placement is load-bearing: per binding user directive the editor must "detect sub-dir in the same dir of the html" — the data directories `data/` and `rpg/data/` must be sub-directories of the HTML's own directory, so the shell loads the live JSON files at runtime instead of carrying a data island (load path: silent `fetch()` probe when the browser permits it, with automatic fallback to a one-click folder pick — see Persistence). Editor state = one in-memory "edited bundle" object; every mutation goes through a mutator that pushes a deep-clone snapshot onto an undo stack (57 nodes ≈ 92 KB raw → snapshots are trivially cheap), with an optional guarded localStorage crash-copy and explicit draft/save-edit download actions.

**(3) Persistence (the pivotal answer — rewritten per binding user directives).** The user rejected the FSA-first recommendation: **"i need firefox … saving temp/final json could be more simple and universal. no api, no server."** The verified browser facts make that rejection even stronger than assumed: **silent `fetch()` of same-directory files from a `file://` page does NOT work in current Firefox either.** Same-directory read access was removed *because it was a vulnerability*: CVE-2019-11730 (Firefox 68, 2019-07-09) — a local HTML file "can use `file:` URIs to access other files in the same directory or sub-directories … **The Fetch API can then be used to read the contents** of any files stored in these directories." Since 68 every local file is a unique **opaque origin** (MDN CORSRequestNotHttp, modified 2025-11-30: "Many browsers, including Firefox and Chrome, now treat all local files as having opaque origins (by default)"), so same-directory/sub-directory resources "no longer satisfy the CORS same-origin rule". The 68-era off-switch `privacy.file_unique_origin` was **removed in Firefox 95** (Bugzilla 1732052); the last remaining escape hatch, `security.fileuri.strict_origin_policy=false`, restores same-dir-or-below reads but is an unsupported security downgrade with removal pending (Bugzilla 1730535 — open, P3). Chrome/Edge block `file://` fetch outright with no setting at all (MDN, same page). Therefore the universal model: **LOAD** = opportunistic silent `fetch()` probe (only when the environment permits) with automatic fallback to the no-API **`<input type="file" webkitdirectory>` folder pick** (Baseline 2025, all major browsers — `File.webkitRelativePath` reveals the sub-directory layout; this is how the editor "detects sub-dir" on default Firefox), plus a single-file `<input type="file">` to reload a downloaded draft. **SAVE** (both the tmp draft and the final per-file save) = the universal `<a download>` + Blob URL pattern — works offline, on `file://`, in every browser, zero APIs, zero servers (MDN `<a>`, modified 2026-05-09: `download` "only works for same-origin URLs, or the `blob:` and `data:` schemes" — a `blob:` URL from a `file://` page qualifies). localStorage is demoted to an optional, guarded, explicitly non-load-bearing crash-recovery copy.

**Primary recommendation:** One generator (`tools/story_editor.py` → committed **repo-root** `story_editor.html`), a data-free shell that loads live sub-directory JSON at runtime (fetch-probe → `webkitdirectory` folder pick → single-file draft reload), snapshot-stack undo, universal `<a download>`/Blob saves (draft = one bundle file the human saves into git-ignored `tmp/`; final = per-dirty-file downloads with displayed repo-relative destinations), paste-in scene capture validated against the known MolAction op set, and Python-side tests treating the emitted HTML as data; all runtime GUI behavior = human-verify checkpoints (**Firefox first**, per user directive).

### scene_capture paste contract (B8)

`render_capture` (committed `tools/scene_capture.py`:416–434) emits **jsonc**: `//`-header comment lines, then **one JSON array** of MolAction dicts (`{op, target, args}`), then `# NOT CAPTURED: …` note lines. The frozen op vocabulary it emits (:18–24): `set_color / show_as / color / show / label / select_focus / zoom` + exactly one Phase-10-flagged `set_view`; `load`/`hide_all` are never emitted (replay-side) — but they DO appear in existing `on_enter` data (e.g. `gly.start` starts with `hide_all`). Editor paste UX: textarea → strip lines beginning `//` or `#` → take first `[` … last `]` → `JSON.parse` → per-entry validation: object with string `op`; allowlist `{set_color, show_as, color, show, label, select_focus, zoom, set_view, set, edit, align, load, hide_all}` (the superset observed in the committed viewer's `summarize_on_enter` :263–309); **warn-but-accept unknown ops** (extensibility, B11) and flag `set_view` with the Phase-10 warning text. Preview renders each op via the same summary mapping as `summarize_on_enter`, then attaches to `node.on_enter`.

- **Placement at repo root is load-bearing, not cosmetic.** The directive requires the HTML to find data in sub-directories *of its own directory*: relative paths like `data/story_glucose/manifest.json` and `rpg/data/edits.json` must resolve from the HTML's location. Only the repo root satisfies this — in `tools/` the data would be a *sibling* (parent-directory reads are blocked by the origin policy; see Persistence). Verified 2026-09-04: `git check-ignore story_editor.html` → not ignored (exit 1); `git show HEAD:.gitignore` ignores only `dist/`, `tmp`, wheels/caches/secrets — the root is committed territory. Never emit to `dist/` (the viewer's default — git-ignored). **Never** edit `.gitignore` (concurrent agent owns it).
- **The folder-pick load path tolerates a moved HTML** (the picker is location-independent), but the silent fetch-probe path and the human's mental model require repo-root placement; the boot panel always displays the expected sub-directory layout so a misplaced copy is self-explaining.
- The plugin zip bundles **only `rpg/` + `data/story_glucose`** (`tools/build_plugin_zip.sh` staging) — a root-level `story_editor.html` never ships, satisfying "authoring tool, not runtime code" (ROADMAP :294).
- `tmp` (any file/dir named `tmp`) is git-ignored → the human saves the downloaded draft as `tmp/story_editor_draft.json` and it never touches git, exactly matching ROADMAP E ("draft = tmp file (git-ignored)").

**Installation:** none. Generator runs via `python3.6 tools/story_editor.py`; the HTML runs by double-click — **Firefox is the user's declared browser** (directive), and the folder-pick + download flows behave identically in Chrome/Edge/Safari. Zero dependencies (A), zero servers (A + directive).

### Recommended in-browser editor architecture (vanilla JS)

```
┌─────────────────────────────────────────────────────────────────────┐
│ LOAD:  silent fetch("data/story_glucose/manifest.json") probe first  │
│   (succeeds only if the browser permits file:// reads — NOT the      │
│   default anywhere since Firefox 68 — then the whole target set      │
│   auto-loads); on rejection → the universal pick panel:              │
│   <input type="file" webkitdirectory multiple> = "select your repo   │
│   folder"; File.webkitRelativePath matched against the expected      │
│   sub-dir paths (data/story_glucose/*.json, data/citations.json,     │
│   data/sources.json, rpg/data/edits.json, rpg/data/cast.json)        │
│   → found/missing checklist banner. Draft reload: single-file        │
│   <input type="file"> restoring a downloaded draft bundle.           │
├─────────────────────────────────────────────────────────────────────┤
│ STATE  = { bundle, dirty:set<fname>, undo:[], redo:[], sel:id,       │
│            fingerprints:{fname: fnv1a(rawText at load time)} }       │
│ MUTATE = every change flows through mutators:                        │
│   function apply(action){ snapshot(); action.redo(STATE.bundle);     │
│     STATE.dirty.add(action.file); scheduleDraftSave(); rerender(); } │
│ VIEWS  = SVG graph (left, zoom/pan) + node form panel (right) +      │
│          path-trace panel + claims panel (C)                         │
│ PERSIST= draft = one <a download> bundle → human saves into tmp/     │
│          final = per-dirty-file <a download>s, each row showing its  │
│          repo-relative destination; optional debounced localStorage  │
│          crash copy (guarded, explicitly NON-load-bearing)           │
└─────────────────────────────────────────────────────────────────────┘
```

Key structural choices:

1. **Edit the raw bundle, not the derived model.** Keep `files[fname].nodes[id]` as the source of truth (ordered objects — Python 3.6 dict order is preserved by `json.dumps` and JS object key order for string keys); re-derive the display model (kinds/edges/positions) after each mutation. This mirrors the viewer's load→derive split and guarantees round-trip fidelity. **Preserve unknown keys** (extensibility B11): mutators touch only known fields; never rebuild nodes from a fixed field whitelist.
2. **Event delegation** on containers (graph SVG + panel lists) — one `click`/`input` listener per container, dispatch on `data-*` attributes. No per-row listeners (57 nodes × N choices × form fields adds up and breaks on re-render).
3. **Rerender strategy:** full rerender of the SVG + panel per mutation is fine at this scale (57 nodes; the working-copy viewer already does full-rerender SVG at 248 KB emitted). Keep zoom/pan transform in view state that survives rerender.
4. **Selection-driven editing:** click node → form panel shows every editable aspect (B2 type via `is_ending` + tags; B3/B4/B5 choice list with goto/weight/cond/effects/tags; B6 texts; B7 cast linkage; B8 on_enter list; B10 pool membership). This covers B1–B10 with ONE interaction model (form panel), keeping graph interactions minimal (below).

### Persistence — universal no-API model (rewritten per binding user directives)

**Directives (verbatim):** "i need firefox, should be able to detect sub-dir in the same dir of the html" + "so saving temp/final json could be more simple and universal. no api, no server."

| Option | Status under the directives |
|---|---|
| (a) File System Access API (`showSaveFilePicker` etc.) | **REJECTED by user directive** — Firefox never shipped it (caniuse, Sep 2026; Mozilla position "harmful") and the user wants Firefox + simple/universal, not per-browser picker machinery |
| (b) `<a download>` + Blob URL downloads | **PRIMARY** for both draft and final save — universal, offline, `file://`-safe, zero APIs |
| (c) localStorage | OPTIONAL guarded crash-recovery only — explicitly **non-load-bearing** (user's simplicity directive) |
| (d) Patch-file + Python applier | Deferred (non-MVP) — future *atomicity* hardening |
| LOAD via silent fetch of sub-dir JSONs | Opportunistic **probe only** — `file://` fetch is blocked by default in ALL major browsers, **including Firefox ≥68** (see Pitfall 2) |
| LOAD via `<input webkitdirectory>` folder pick + single-file draft reload | **PRIMARY** — no API, no server, every browser (`File.webkitRelativePath`, Baseline 2025) |

The hard constraint underneath the directive: **no browser reads same-directory files from a `file://` page by default anymore.** Firefox removed same-dir read access in 68 because it *was* the vulnerability (CVE-2019-11730 — "The Fetch API can then be used to read the contents of any files stored in these directories" is the advisory's description of the flaw); `privacy.file_unique_origin` (the 68-era pref) was removed in Firefox 95 (Bugzilla 1732052); `security.fileuri.strict_origin_policy=false` is the sole remaining bypass — an unsupported security downgrade with removal pending (Bugzilla 1730535, open, P3; dveditz: "no one is worrying about making sure new features work when this is set to false"). Chromium blocks `file://` fetch outright, no setting. **So the editor detects sub-directories opportunistically and loads them with user-granted file access.**

**LOAD — boot sequence (all paths no-API):**

1. **Silent probe (opportunistic):** `fetch("data/story_glucose/manifest.json")` relative to the document, then `rpg/data/edits.json`. On success (only when the environment permits: a voluntarily-run `python -m http.server`, or a consciously relaxed pref) → auto-load the full target set via fetch → green banner "Data auto-detected in sub-directories". On rejection — **the default on `file://` in Firefox ≥68, Chrome, Edge, Safari** — fall through to 2. Rejection is *expected and handled*; it is never an error state and never a silent failure (the pick panel explains why).
2. **Folder pick (primary universal path):** `<input type="file" webkitdirectory multiple>` — one click, "Select your repository folder". Walk `File.webkitRelativePath` (Baseline 2025 — all major browsers, MDN) and match against the fixed expected-path list: `data/story_glucose/manifest.json` (+ the story files the manifest lists), `data/citations.json`, `data/sources.json`, `rpg/data/edits.json`, `rpg/data/cast.json`. Use a `/`-boundary suffix match so picking a parent of the repo also works; picking a *child* folder (e.g. `data/`) yields no match by design — the checklist then says "select the repository root". Security rules: the FileList contains the whole picked tree **including `.git`** — filter against the expected paths, never enumerate blindly; reject any path containing `..`, a drive letter, or a leading `/`; load only matched files in memory (`FileReader`/`file.text()`); treat paths as case-sensitive exactly as committed (repo paths are lowercase).
3. **Layout banner (the "detect sub-dir" UX):** after either path, a checklist of every expected path with found/missing state (e.g. `data/story_glucose/tca.json ✓` / `rpg/data/edits.json ✗ — expected under the folder you picked; did you select the repository root?`). Missing required files block the editor with the expected tree displayed; optional-degrade files (cast) behave as in the viewer.
4. **Draft reload:** single `<input type="file" accept=".json,application/json">` restores a previously downloaded draft bundle — self-contained (edited bundle + dirty set + undo metadata + per-file source fingerprints), so no folder re-pick is needed. If the folder is *also* re-picked, fingerprint comparison warns "underlying files changed since this draft". Fingerprints = 32-bit FNV-1a over each file's raw text (a drift *detector*, not security — fine to hand-roll; no `crypto.subtle` dependency).

**No `../` probes.** A misplaced HTML (copied into `tools/`, `Downloads/`, …) cannot silently reach sibling/parent data — parent-directory reads are blocked by the same origin policy — so the editor never probes parent paths; the fix is placement at repo root, which the boot panel states explicitly. (The folder pick still works from any HTML location — location-independence is a feature of the picker path.)

**SAVE — universal `<a download>` + Blob (both draft and final):**

- **Mechanism (one ~8-line helper, Code Example 3):** `URL.createObjectURL(new Blob([json], {type:"application/json"}))` → temp `<a download="name.json">` → `click()` → revoke. Works offline, on `file://`, in every browser, zero APIs (MDN `<a>`, modified 2026-05-09: `download` applies to `blob:`/`data:`/same-origin URLs; Baseline widely available since July 2015).
- **Draft** (ROADMAP E, "tmp file (git-ignored)"): one download — a self-contained draft JSON `{version, saved_at, bundle, dirty:[…], undo_meta:{undo_depth, redo_depth}, fingerprints:{fname: hash}}` — with "save as `story_editor_draft.json` into the repo's `tmp/` folder" displayed next to the button. (Undo *stacks* are not serialized — a reloaded draft starts with fresh undo history but intact dirty-state; the bundle is the session.)
- **Final save** ("save edit" = **only dirty files**): a save panel with one row per dirty file — `[Download] tca.json → save over data/story_glucose/tca.json` — plus an opt-in "Download all (N)" that fires rows sequentially with ~400 ms gaps (browsers may prompt once for multiple downloads; per-file buttons are the default precisely to avoid that). JSON emitted with `JSON.stringify(x, null, 2)` to match repo style. After saving, the panel reminds the human to run the Python gates (`python3.6 tools/story_graph_viewer.py`, the suite) — the editor cannot see the filesystem, so the Python gates are the only authoritative post-save check.
- **Filename honesty:** the `download` attribute's filename is a **suggestion** — browsers may adjust it and user settings change behavior entirely (MDN `<a>`, 2026-05-09). A Firefox-specific claim ("suggested name ignored for blob: downloads on `file://` pages") could **not** be verified from any fetched source despite a targeted search on 2026-09-04 — **unconfirmed either way**; the design is indifferent: every save affordance displays the exact expected filename + destination, and the recommended setting below makes naming explicit anyway.
- **Recommended one-time user setup (documented in the editor's help):** Firefox → Settings → General → Files → **"Always ask you where to save files"**. Then every download button opens a save dialog where the human picks the exact name and location — the draft lands in `tmp/`, final files overwrite `data/story_glucose/*.json` in place. This is the closest thing to "saving in place" that exists without an API or a server, and it neutralizes both the Downloads-folder shuffle and any filename-suggestion quirk.
- **localStorage:** optional, guarded (MDN `storageAvailable()` try/catch), debounced crash-recovery copy only; restored via a "draft from earlier session found — restore?" banner. Failure is swallowed silently; nothing in the load/save flow depends on it.
- **No servers, no POST, no dev-server requirement** (A + directive). The fetch-probe path is a free bonus when the human *chooses* to serve the folder; it is never required.

**Rejected by user directive (for the record):** File System Access API — Firefox never shipped it and the user required Firefox + simplicity; the download model above is strictly more universal. Re-permission prompts and picker fatigue are thereby **moot**, not mitigated.

### Undo/redo (E)

- **Snapshot stack, not diffs.** One undo entry = full deep-clone of the edited bundle (`JSON.parse(JSON.stringify(bundle))`). At 57 nodes / 92 KB raw this is microseconds and megabytes at worst; a 200-entry cap bounds memory. Diff-based (JSON-patch) or per-field history buys nothing at this scale and is the classic source of subtle undo bugs.
- **Granularity = one logical action** (add node, delete choice, paste on_enter, edit one field commit). Text inputs commit their snapshot on `change` (blur) — not per keystroke — so typing "aconitase" is one undo step. New action clears the redo tail. Undo/redo also flip the file's dirty bit and re-run validation badges.
- **Draft autosave cadence:** debounced 500–1000 ms after the last mutation (not every keystroke, not on a timer while idle) — and that debounced write is only the *optional guarded localStorage crash-copy*; the explicit "Save draft" button forces an immediate draft **download** (the human saves it as `tmp/story_editor_draft.json`).

### Graph editing UX — minimal interaction set covering B1/B2/B5

The data has **no layout fields** — positions derive from column (file) / row (manifest order) exactly as in the viewer (:60–85, :329–349). Therefore:

- **Connections + direction (B5) = editing `choice.goto`.** An edge's direction is inherent (src → dst). The primary interaction is a **dropdown of existing node ids** on each choice row (grouped by file), with typeahead — click-source-click-target or drag-from-port wiring is nice-to-have but NOT needed; the goto dropdown is unambiguous, keyboard-accessible, and cannot create invisible state.

### Anti-patterns to avoid

- **Do not** make the editor *depend* on `fetch()` for local data — `file://` fetch is blocked by default in **every** major browser, **including Firefox since 68** (unique opaque origins, CVE-2019-11730). Use it only as the opportunistic boot probe, always with the folder-pick fallback. (The viewer's data island remains a valid pattern *for the viewer*; the editor deliberately diverges per directive — runtime sub-directory load.)
- **Do not** use `<script type="module">` or ES-module imports — module scripts fail under `file://` CORS; use one classic inline script.
- **Do not** persist layout coordinates into the story JSON (no such schema; the engine/gates don't know them).
- **Do not** rebuild nodes with a fixed whitelist of fields — unknown keys must round-trip (B11 extensibility + engine tolerance).
- **Do not** modify `tools/story_graph_viewer.py` or `.gitignore` (concurrent agent owns both; both have uncommitted changes right now).

## Common Pitfalls

### Pitfall 1: localStorage on `file://` is NOT portable
**What goes wrong:** Draft autosave silently fails (or silently shares across ALL local files) depending on browser.
**Why:** Storage is strictly per-origin (MDN Web Storage, 2026-05-26); the HTML spec throws `SecurityError` on storage access from an opaque origin; browsers disagree on whether a `file://` document is opaque. Chrome's behavior (works, shared `file://` origin) and Firefox/Safari behavior are per-browser details I could not re-verify from a fetched source today — treat as **LOW confidence** per browser.
**How to avoid:** (1) Primary draft = a downloaded tmp file per ROADMAP E (universal `<a download>` — see Persistence); (2) localStorage only as guarded crash-recovery via the MDN `storageAvailable()` try/catch, wrapped so any throw is swallowed, and **explicitly optional/non-load-bearing** per the user's simplicity directive; (3) never store the only copy of work there.
**Warning signs:** "Save draft" works in the dev browser but throws SecurityError in another.

### Pitfall 2: `file://` fetch is blocked by default in ALL major browsers — including current Firefox
**What goes wrong:** A boot sequence built on "Firefox can fetch same-directory files on `file://`" (the assumption in the original directive framing) fails on the user's own machine — the exact opposite of the directive's intent, and easy to miss because the code *worked* in some old tutorial.
**Why:** That behavior died in 2019. Firefox 68 (CVE-2019-11730, MFSA 2019-21, announced 2019-07-09) made every local file a unique opaque origin precisely because same-directory Fetch access was an attack vector ("The Fetch API can then be used to read the contents of any files stored in these directories"). MDN's CORS error page (modified 2025-11-30) states browsers "now treat all local files as having opaque origins (by default)". The 68-era off-switch `privacy.file_unique_origin` was **removed in Firefox 95** (Bugzilla 1732052); `security.fileuri.strict_origin_policy=false` still restores same-dir-or-below reads (parent/sibling stay blocked) but is an unsupported downgrade with removal pending (Bugzilla 1730535, **open**, P3 — "no one is worrying about making sure new features work when this is set to false"). Chromium has no setting at all. Never ship instructions to flip prefs; at most document it as "not recommended".
**How to avoid:** fetch is the opportunistic boot probe only; the `webkitdirectory` folder pick is the primary path; every fetch rejection routes to the pick panel with a clear explanation — an explicit unsupported-environment notice, **never silent failure and never a dead "loading…" state**.
**Warning signs:** Planning docs or JS comments claiming "Firefox allows file:// fetch of sub-directories"; a boot flow whose only load path is fetch; no user-granted file-access fallback.

### Pitfall 3: Multi-file save under the download model — ordering, collisions, misplacement
**What goes wrong:** One logical edit can dirty up to 9 files (7 story + `rpg/data/edits.json` + `rpg/data/cast.json`); downloads land in the browser's download directory where same-name files get `(1)`/`(2)` suffixes, and nothing verifies the human moved them to the right place — a JSON saved into the wrong sub-directory silently corrupts the bundle layout the gates expect.
**How to avoid:** Track dirty **per file**; the save panel shows one row per dirty file with the exact filename and its repo-relative destination (`tca.json → data/story_glucose/tca.json`); default to per-file buttons (the batch "Download all" is opt-in, sequential with gaps, and may trigger the browser's multiple-download prompt); recommend the one-time **"Always ask you where to save files"** setting so each save goes directly to its real location; after any final save, remind the human to run the Python gates — the editor cannot see the filesystem, so the gates are the only authoritative post-save check.
**Warning signs:** "Download all" firing without spacing (browser may drop downloads); destination labels omitted from save rows; no post-save gate reminder.

### Pitfall 3b: download filename is a suggestion, not a guarantee (file:// blob-name caveat UNVERIFIED)
**What goes wrong:** The editor requests `tca.json` but the human finds `download.json`, `tca(1).json`, or a MIME-derived name in the Downloads folder.
**Why:** MDN (`<a>`, modified 2026-05-09) documents the `download` value as a *suggested* filename: browsers adjust for filesystem rules, and user settings change behavior entirely. A Firefox-specific quirk (ignoring the suggested name for blob: downloads on `file://` pages) **could not be verified** from Bugzilla/MDN despite a targeted search on 2026-09-04 — treat as unconfirmed in both directions.
**How to avoid:** Never rely on the attribute alone: every save affordance displays the exact expected filename and destination; the draft bundle stores the intended per-file names so the final-save panel regenerates correct names regardless of what the browser saved; the "Always ask where to save" recommendation makes the human confirm the name explicitly.
**Warning signs:** Tests or docs asserting the downloaded file *will* bear the attribute's name.

### Pitfall 3c: `webkitdirectory` hands the editor the ENTIRE picked tree (including `.git`)
**What goes wrong:** Naively iterating `input.files` reads thousands of `.git` objects (slow), or matches case-drifted paths on Windows, or trusts unvalidated paths — wrong or unsafe.
**Why:** The folder pick enumerates everything recursively; `webkitRelativePath` preserves on-disk casing and (per spec) contains no `..`, but nothing stops sloppy matching.
**How to avoid:** Match each file's relative path against the fixed expected-path list with a `/`-boundary suffix comparison; reject anything containing `..`, a drive letter, or a leading `/`; load only matched files; treat paths as case-sensitive exactly as committed (repo paths are lowercase); picked content never leaves memory.
**Warning signs:** Load time scaling with repo size; "file not found" for paths whose case differs from the commit.

### Pitfall 4: Emitted-HTML hazards (data island + script breakout)
**What goes wrong:** Story text contains `</script>` (breaks out of the data island) or non-7-bit characters (encoding surprises); `.format()` on the template explodes on JS braces; `<script type="module">` fails on `file://`.
**Why/how to avoid:** The viewer already solved these — `json.dumps(..., ensure_ascii=True)` + `.replace("</", "<\\/")` on the payload, template substitution via `str.replace` tokens only, one classic inline script. Copy that discipline. **Note for this editor:** the shell interpolates **no story data** (runtime sub-directory load per directive), so the breakout exposure shrinks to any interpolated static constants — keep the discipline anyway. (The `</`-escape discipline specifically mattered for the data island, which the editor no longer has.)
**Warning signs:** Generator tests should assert zero `__UPPERCASE__` token leaks and that any interpolated constants substituted correctly (there is no data island to round-trip anymore).

### Pitfall 5: Wrong placement of the committed HTML
**What goes wrong:** Editor HTML emitted to `dist/` (viewer's default) is **git-ignored** — the "committed artifact" decision silently fails; HTML emitted anywhere but the repo root breaks the sub-directory contract (data must sit *below* the HTML's directory for the probe path; a misplaced copy can only load via folder pick).
**Why:** Committed `.gitignore` ignores `dist/` + `tmp`; browsers block parent-directory reads.
**How to avoid:** The generator writes **repo-root `story_editor.html`** (verified 2026-09-04: `git check-ignore story_editor.html` → not ignored; root is committed territory). **Never** edit `.gitignore` (concurrent agent owns it).

### Pitfall 6: Verification gaps for JS-heavy artifacts from WSL
**What goes wrong:** No node/npm guaranteed, no headless browser guaranteed — a JS syntax error ships undetected and the editor is a white screen.
**How to avoid:** Automate everything expressible in Python (next section); treat any runtime JS behavior as **human-verify in a real browser** (same split the repo already uses for Qt: automated headless checks + human GUI pass). A cheap extra net: keep the JS in a few large, plain functions and avoid clever syntax; ES2017-level features only (async/await is fine in Chrome/Edge/Firefox/Safari today). **Firefox-first human-verify checkpoints mandated by the directives:** (1) folder-pick load in Firefox with the found/missing checklist; (2) download draft → reload draft via single-file input; (3) per-file final save with Firefox's "Always ask you where to save files" enabled — record what filename Firefox actually uses; (4) the fetch-probe-rejected → pick-panel fallback (the default `file://` path).
**Warning signs:** Generator smoke can only prove structure, not behavior — plan a browser checkpoint task explicitly.

### Pitfall 7: Concurrent-agent collision
**What goes wrong:** Plans that touch `tools/story_graph_viewer.py` or `.gitignore`, or that copy from the viewer's *uncommitted* JS.
**Why:** Both files belong to another agent's workstream. (The viewer's emission was committed as `85a1711` on 2026-09-04 and the tree is clean *today*, but that workstream remains active — treat both files as owned regardless of git state. Amendment noted at the top of this document.)
**How to avoid:** Read the committed versions (`git show HEAD:…`); duplicate needed helpers into `tools/story_editor.py` rather than importing from the viewer; never import viewer modules (its `main` also gates on pinned counts that Phase 8 will legitimately change).

```js
// Load path per directive: "detect sub-dir in the same dir of the html".
// Sources: MDN CORSRequestNotHttp (file:// fetch blocked by default, ALL browsers,
// Firefox >= 68); MDN File/webkitRelativePath (Baseline 2025).
// ES5-style to match this codebase's emitted-JS discipline; classic script (no modules on file://).
var EXPECTED = [
  "data/story_glucose/manifest.json",   // + the story files it lists (validated after load)
  "data/citations.json", "data/sources.json",
  "rpg/data/edits.json", "rpg/data/cast.json"
];
function matchesExpected(relPath) {           // "/"-boundary suffix match: a parent of the repo also works
  for (var i = 0; i < EXPECTED.length; i++) {
    var p = EXPECTED[i];
    if (relPath === p) return p;
    if (relPath.length > p.length &&
        relPath.charAt(relPath.length - p.length - 1) === "/" &&
        relPath.lastIndexOf(p) === relPath.length - p.length) return p;
  }
  return null;
}
function boot() {
  fetch("data/story_glucose/manifest.json", { cache: "no-store" })  // opportunistic probe ONLY
    .then(function (r) { if (!r.ok) throw new Error("probe miss"); return r.json(); })
    .then(loadAllViaFetch)                // only if the browser permits file:// reads (not the default)
    .catch(showFolderPickPanel);          // DEFAULT path on file:// — Firefox >= 68, Chrome, Edge
}
folderInput.addEventListener("change", function (ev) {  // <input type="file" webkitdirectory multiple>
  var found = {}, files = ev.target.files;  // FileList = the WHOLE tree incl. .git — filter, never iterate
  for (var i = 0; i < files.length; i++) {
    var rel = files[i].webkitRelativePath;
    if (rel.indexOf("..") >= 0 || /^[A-Za-z]:/.test(rel) || rel.charAt(0) === "/") continue;
    var key = matchesExpected(rel);
    if (key && !found[key]) found[key] = files[i];
  }
  showLayoutChecklist(found);             // found/missing banner over EXPECTED — the "detect sub-dir" UX
});
```

### 2. Snapshot undo core

```js
// Standard pattern; scale-safe for 57 nodes (~92 KB raw bundle)
var undoStack = [], redoStack = [], MAX_UNDO = 200;
function snapshot() {
  undoStack.push(JSON.stringify(STATE.bundle));     // serialize = deep clone
  if (undoStack.length > MAX_UNDO) undoStack.shift();
  redoStack.length = 0;
}
function undo() { if (!undoStack.length) return;
  redoStack.push(JSON.stringify(STATE.bundle));
  STATE.bundle = JSON.parse(undoStack.pop()); rerender(); }
function redo() { if (!redoStack.length) return;
  undoStack.push(JSON.stringify(STATE.bundle));
  STATE.bundle = JSON.parse(redoStack.pop()); rerender(); }
```

### 3. Draft save (universal download) + optional guarded localStorage crash copy

```js
// MDN storageAvailable pattern: https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API/Using_the_Web_Storage_API
function storageAvailable(type) {
  var storage; try { storage = window[type]; var x = "__storage_test__";
    storage.setItem(x, x); storage.removeItem(x); return true;
  } catch (e) { return false; }
}
// The ONE save primitive — <a download> + Blob URL: zero APIs, works offline and on file://
// (MDN <a>, 2026-05-09: download applies to blob:/data:/same-origin URLs).
// NOTE: a.download is a SUGGESTION — the save panel always displays the expected name (Pitfall 3b).
function downloadText(filename, text) {
  var a = document.createElement("a");
  a.href = URL.createObjectURL(new Blob([text], { type: "application/json" }));
  a.download = filename;
  document.body.appendChild(a); a.click(); a.parentNode.removeChild(a);
  setTimeout(function () { URL.revokeObjectURL(a.href); }, 1000);
}
var draftTimer = null;
function scheduleDraftSave() {            // debounced crash-copy ONLY — optional, non-load-bearing
  if (draftTimer) clearTimeout(draftTimer);
  draftTimer = setTimeout(function () {
    try { if (storageAvailable("localStorage"))
      localStorage.setItem("rpg_story_draft", JSON.stringify(draftDoc())); } catch (e) {}
  }, 800);
}
function saveDraftNow() {                 // "Save draft" button — the real draft (ROADMAP E)
  downloadText("story_editor_draft.json", JSON.stringify(draftDoc(), null, 2));
  report("Save the draft into the repo's tmp/ folder (git-ignored).");
}
function draftDoc() {                     // self-contained: bundle + dirty set + undo meta + fingerprints
  return { version: 1, saved_at: new Date().toISOString(),
           bundle: STATE.bundle, dirty: Object.keys(STATE.dirty),
           undo_meta: { undo_depth: undoStack.length, redo_depth: redoStack.length },
           fingerprints: STATE.fingerprints };   // fnv1a per source file — drift detection on reload
}
```
