## Decisions Made
See `key-decisions` in the frontmatter; the load-bearing ones:
- **"(none — invalid)" is an intentional invalid state**: the empty goto option commits `""` (not null), which the validator's dangling_divert rule flags — a none-target is always visible and always loud, honoring "make dangling visible" without inventing a legal null shape the engine never produces.
- **Weight locking is a context gate, not a node-id gate**: the plan's wording (rng:weighted tag OR any choice carries weight) is implemented literally; on a non-shuffle node where the context is somehow true (e.g. the tag was just added), the weight input unlocks but the weight_outside_shuffle note + validator error keep the determinism pin enforced.
- **Effects edits are bundle-based, not DOM-rebuild-based**: blur-commit ordering makes DOM == bundle between events, so rename/value/remove/add each compute from the bundle and commit exactly ONE apply (the earlier DOM-collect design was replaced during development as strictly simpler and race-free).
- **Choice-field commit granularity matches the core contract**: change commits one apply; input only refreshes display (row chips + the single-Continue hint via an overrides object) — the bundle is never written on input.
