## Decisions Made
- **Status bar = navigation too**: the dirty field jumps to the Save tab and the validate field to Diagnostics, so the always-visible bar doubles as the error path into the one-click health report (the plan's click-through requirement, made symmetric).
- **First-open detection without a tab event**: the core's `showTab` is programmatic (no event), so the chrome adds its own delegated `#tabbar` listener AND routes the status-bar jump through the same `onDiagnosticsOpened()` — the self-test auto-runs exactly once regardless of entry path, per the plan's "auto-runs once on first open".
- **Sibling-owned status children are preserved, not rewritten**: the bar rebuild uses innerHTML but captures `#statusbar-serializer` before and re-appends after — 05_json's boot canary survives every rerender without either asset writing into the other's file.
- **The Diagnostics validator panel reuses `countShifts` verbatim** from the 07.1-08 verdict (nodes/tiers/editAllowed old→new + pinnedTests + viewerConstants) instead of re-deriving counts — one source of truth, drift impossible.
- **The Help tab lists all FIVE post-save commands including `check_edit_coverage.py`** (the 80_save reminder lists four; the plan's Help spec mandates the coverage gate too — the Help tab is the complete manual).
