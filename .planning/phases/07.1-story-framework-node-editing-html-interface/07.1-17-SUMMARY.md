## Decisions Made
See `key-decisions` in the frontmatter; the load-bearing ones:
- **Three surfaces, not one**: the form aside is hidden until selection (40_form's landed behavior, not mine to change), so the toolbar lives directly on `#tab-graph` and overlays on a body-level host — the plan's "adds its toolbar buttons into the graph tab via delegated listeners on its own container only" is implemented literally, with zero listener overlap with any sibling container.
- **Wizard ending seed = acknowledgment, recipe = hard block**: the orphan BFS block applies where an inbound edge is POSSIBLE (existing node); the wizard (new node, zero inbound by definition) requires the explicit orphan checkbox instead — the reachability gate still goes visibly RED until the parent is wired, and the post-create note names the next step.
- **Exact-redo-on-clone simulation**: the acknowledgment preview and the eventual apply share one redo function, so the pinned-count preview can never disagree with what lands.
- **Prefill by synthesized human event**: the Data-tab bucket handoff fires the sibling's own change delegation path rather than reaching into its closure — contained, defensive, and ownership-clean.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] In-panel manifest export for manifest.json edits**

- **Found during:** Task 1 (make-starting-node + new-file flows)
- **Issue:** the plan's recipes edit `manifest.start` / append to `manifest.files` via `apply()`, but the landed Save tab serializes `bundle.files` + the 4 registries only (80_save.js `fileContentOf` has no manifest branch) — a dirty `manifest.json` renders a warn row ("No in-memory content found") with NO download path, leaving the mandated manifest edits unsaveable; 80_save.js is not this plan's file and no extension hook exists (downloadText is closure-private).
- **Fix:** while `manifest.json` is dirty, the lifecycle section renders the export box — house-style manifest JSON in a readonly textarea + a 3-stage copy button (navigator.clipboard → execCommand → select-in-place, the 60_trace precedent) + the exact destination `data/story_glucose/manifest.json` + the persistent-dirty-dot caveat (the core's recomputeDirty re-marks files it cannot re-diff, the same documented 80_save registry limitation).
- **Files modified:** tools/story_editor_assets/45_lifecycle.js
- **Verification:** battery asserts MANIFEST_FNAME + MANIFEST_DEST wiring; suite green
- **Committed in:** be13bb8 (Task 1 commit)

**2. [Rule 1 - Bug] Non-enumerable id stamp missing on raw-action node creation**

- **Found during:** Task 1 (post-draft review of the create flow)
- **Issue:** the create action assigns the seeded node into `file.nodes[id]` via a RAW action (not the core's `nodeAdd`), so the new node lacked the non-enumerable `id` stamp — `deriveKind`/40_form's id-as-title would read `node.id === undefined` until a snapshot restore re-stamped it.
- **Fix:** `stampNodeId(n, id)` mirrors 00_core's defineProperty contract (enumerable: false — JSON-invisible, saved bytes unchanged) inside the create redo; applied to both the simulation clone and the real bundle harmlessly.
- **Files modified:** tools/story_editor_assets/45_lifecycle.js
- **Verification:** battery's bracket/structure gates + suite green; the form's node.id consumption is display-only
- **Committed in:** be13bb8 (Task 1 commit)
