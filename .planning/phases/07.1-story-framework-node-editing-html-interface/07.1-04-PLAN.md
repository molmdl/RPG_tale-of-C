Write the FIRST asset file (sorted first → inlined first → defines `window.EDITOR`). Classic script, ES5-style, one IIFE, **no modules** (modules fail on file://). Contents:

1. **Namespace + init registry**: `window.EDITOR = { version: '0.1.0', _inits: [], init: fn push, runInits: run all registered }`.
2. **injectCss(css)**: creates a `<style>` and appends to head (per-asset CSS co-ownership; shell keeps only structural styles).
3. **State**: `EDITOR.state = { bundle: null, dirty: {}, fingerprints: {}, sel: null, loadedAt: null }` where `bundle = { files: {fname: {nodes: {id: node}}}, manifest, citations, sources, edits, cast, order: [fnames] }` — **the raw bundle is the source of truth** (ordered objects; JS preserves string-key order); the display model re-derives after each mutation. `dirty` = fname → true. Fingerprints = FNV-1a 32-bit hex per raw file text (implement fnv1a; RESEARCH-UI Code Example 3 note: drift detector, not security).
4. **setBundle(bundle, rawTexts)**: replaces state, resets undo/redo, computes fingerprints from rawTexts, marks nothing dirty.
5. **Undo/redo**: snapshot stacks of `JSON.stringify(EDITOR.state.bundle)`, MAX_UNDO = 200, `apply(action)` = push snapshot → action.redo(bundle) → mark action.files dirty → clear redo tail → `EDITOR.afterChange()`; `undo()` / `redo()` per RESEARCH-UI Code Example 2 (also re-marking dirty from the restored state — recompute dirty by comparing restored bundle per-file JSON against the ORIGINAL loaded per-file JSON snapshots kept in `EDITOR._ originals`); `EDITOR.afterChange()` calls the rerender dispatcher + the (optional, registered-later) validator hook + draft-scheduler hook via `EDITOR.hooks = { rerender: [], validate: [], persist: [] }` and iterates them defensively (try/catch each hook so one broken view never kills the state layer).
6. **Text-edit granularity**: provide `EDITOR.textFieldBindings(container)` — delegated `change` (not `input`) handler for `input[data-field]`/`textarea[data-field]` elements that commits via apply() on blur/change (one undo step per field commit), plus a live-preview update on `input` that does NOT snapshot.
7. **Unknown-key preservation contract**: mutator helpers `EDITOR.nodeGet(fname,id)`, `EDITOR.nodeSet(fname,id,field,value)` (touches ONLY the named field), `EDITOR.nodeAdd/Delete`, `EDITOR.choiceAdd/Update/Delete` — never rebuild a node from a whitelist (B11; RESEARCH-UI anti-pattern 4). Document in a comment: unknown keys round-trip.
8. **Selection + tabs**: `EDITOR.select(nodeId|null)` sets state.sel, dispatches `EDITOR.hooks.rerender`; `EDITOR.showTab(name)` toggles `.active` on nav buttons + containers; registered per-view renderers via `EDITOR.view(name, renderFn)`; `rerender()` invokes every registered view + the node form hook.
9. **Helpers**: `esc(s)` HTML-escape; `delegate(container, evType, attr, fn)` event delegation by data-* attribute (one listener per container — RESEARCH-UI structural choice 2); `nodeById(id)`; `fileOfNode(id)`; `allNodes()` iterator; `derivedKind(node)` port of the viewer's derive_kind precedence (ending > phase8-stub > edit-prompt > restored > rng > edit-allowed > story; ids list: fa.stub/alc.stub/edit.prompt/gly.pfk_restored/tca.aconitase_restored) — cite `git show HEAD:tools/story_graph_viewer.py:206-228` in a comment; `endingTier(node)` from is_ending ONLY (never the ending:* tag — 3 anaerobic endings lack it, RESEARCH-DATA Pitfall 15).
10. **Test fixture loader**: `EDITOR.loadBundleForTest(obj)` — lets the page be driven from an injected object (used by later diagnostics/self-tests; harmless in production).
11. Asset CSS: minimal injected styles for status bar + tab active states (co-owned here).
12. Header comment: asset order contract (00 loads before all), file-ownership note (this file is 07.1-04's; later plans own their own files).
