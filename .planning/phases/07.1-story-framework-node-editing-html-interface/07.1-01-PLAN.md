  <files>tools/story_editor.py, tools/story_editor_assets/shell.html</files>
  <action>
Create `tools/story_editor.py` — Python 3.6, stdlib only (json/os/sys/html), **NO f-strings** (suite style: `.format()` / `%` / concatenation), CWD-independent paths (SCRIPT_DIR/REPO_ROOT like the committed viewer). Mirror the viewer's discipline (read `git show HEAD:tools/story_graph_viewer.py` for style; do NOT import it):

1. **Load live data** (nothing embedded): `data/story_glucose/manifest.json` + the 7 story files it lists, `data/citations.json`, `data/sources.json`, `rpg/data/edits.json`, `rpg/data/cast.json` — relative to REPO_ROOT.
2. **Generation-time structural sanity gate** (gates the CURRENT data, embeds NOTHING): JSON parse errors, duplicate node ids across files (the graph.py:76-80 ValueError class), missing manifest-listed file, `choice.goto` target not in the node set, `manifest.start` not in the node set. On violation print `EDITOR_FAIL: <reason>` and exit 1 WITHOUT writing HTML. Deliberately do NOT pin 57/21/15 counts here — counts legitimately change in Phase 8; count-shift detection belongs to the validator plans (07.1-03/08).
3. **Asset pipeline**: auto-discover `tools/story_editor_assets/shell.html` + `tools/story_editor_assets/*.js` (sorted by filename). Read each, inline into the emitted page. Assets are concatenated as separate classic `<script>` blocks in sorted order between the shell's script slots. If the assets dir has no JS yet, emit the shell alone (later plans add files without touching this generator).
4. **Token substitution via `str.replace` ONLY** (never `.format()` — JS/CSS braces explode): `__TITLE__`, `__GENERATED_AT__` (ISO timestamp), `__ASSET_MANIFEST__` (an HTML comment listing inlined asset filenames + byte sizes, for traceability). HTML-escape interpolated constants (`html.escape`).
5. **Emit to repo root**: `<REPO_ROOT>/story_editor.html`. NEVER `dist/` (git-ignored — the committed-artifact decision would silently fail) and never `tools/` (load-bearing placement: data dirs must be sub-directories of the HTML's own dir — RESEARCH-UI "Recommended file layout" + Pitfall 5). Support `--output PATH` override for tests (default repo root). Print a one-line summary: emitted path + asset count + total bytes.
6. CLI: `python3.6 tools/story_editor.py [--output PATH] [--story-dir DIR]`. Argparse-free simple parsing or argparse (stdlib) — your choice; keep Python 3.6 compatible.

Create `tools/story_editor_assets/shell.html` — the page skeleton (dumb markup, no behavior):
- `<meta charset="utf-8">`, viewport, `<title>` token.
- `#boot-panel`: mount point for the load UI (probe status line, folder-pick input mount, found/missing checklist container, draft-reload input mount). Include static explanatory copy: expected sub-directory layout (`data/story_glucose/*.json`, `data/citations.json`, `data/sources.json`, `rpg/data/edits.json`, `rpg/data/cast.json` must sit below this HTML's directory) and the note that the folder pick works from any location.
- Tab nav with buttons for: Graph | Trace | Claims | Data | Save | Diagnostics | Help (data-tab attributes), each with an empty content container `#tab-graph`, `#tab-trace`, `#tab-claims`, `#tab-data`, `#tab-save`, `#tab-diagnostics`, `#tab-help`.
- `#node-form` sidebar container (hidden until a node is selected) with FIXED sub-sections (later plans mount into these by id — never into each other's files): `#node-form-identity` (07.1-09: texts/claims/tags), `#node-form-choices` (07.1-15), `#node-form-onenter` (07.1-16), `#node-form-lifecycle` (07.1-17); plus `#statusbar` (dirty/undo/state summary).
- A `<style>` block for layout only (flex/grid skeleton, tab bar, monospace JSON areas). Per-feature CSS is injected by each JS asset later — the shell holds only structural styles.
- Script slots: after the markup, one `<script>` block placeholder comment per asset (the generator replaces a single `/*__ASSETS__*/` marker with the concatenated asset blocks), then a tiny classic inline bootstrap: `window.addEventListener('DOMContentLoaded', function () { if (window.EDITOR && EDITOR.runInits) EDITOR.runInits(); });`
