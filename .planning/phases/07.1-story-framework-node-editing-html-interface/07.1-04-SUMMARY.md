## Decisions Made
See `key-decisions` in the frontmatter; the load-bearing ones:
- **Non-enumerable id stamp**: nodes must stay pristine for byte-faithful saves, yet `deriveKind(node)`/form bindings need `node.id` — a non-enumerable property is invisible to `JSON.stringify`, `Object.keys` and `for-in`, so saved bytes never change; snapshot restores re-stamp from the dict keys.
- **Live preview never writes the bundle**: if `input` mutated the node, the change-commit's snapshot would already contain the typed value and text undo would be broken. Preview subscribers (`EDITOR.livePreview`) receive `{node, file, field, value, el}` per keystroke; only `change` commits.
- **Undo/redo re-derive dirty from `_originals`** (the plan's requirement): action-based dirty bookkeeping cannot survive time travel; the load-time per-file JSON snapshots are the only honest baseline.
- **Core's rerender dispatcher is `hooks.rerender[0]`**: `afterChange()` and `select()` both fan through the same defensive dispatch; 07.1-08 adds `hooks.validate`, 07.1-13 adds `hooks.persist` — all iterated with per-hook try/catch.
