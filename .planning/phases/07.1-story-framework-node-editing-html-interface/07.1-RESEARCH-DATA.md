# Phase 7.1: Story Framework Node Editing HTML Interface — DATA MODEL & EDIT CONTRACTS Research

**Researched:** 2026-09-04
**Domain:** Story-bundle JSON schemas (7 story files + manifest), edits/cast manifests, citation registry — and every gate an editor write can break
**Confidence:** HIGH (all claims below verified by reading the files/code in this repo on 2026-09-04; every schema claim carries a file:line citation)

## Summary

The editor's write surface is **six flat JSON files + one flat registry**: `data/story_glucose/manifest.json` (14 lines), 7 story files shaped `{"nodes": {id: {...}}}` (57 nodes total, uniform 6-key schema + optional `is_ending`), `rpg/data/edits.json` (13 enzyme buckets), `rpg/data/cast.json` (12 entries), `data/citations.json` (77 claims, flat dict) and `data/sources.json` (81 records, flat dict). There is **no `node_type` field, no `tier` field, no `on_enter_divert` in the data** — node kinds are *derived* (ending/stub/edit-prompt/restored/rng/edit-allowed/story) from `is_ending`, node id, `choices[].weight`, and tags. All 57 nodes carry exactly the same 6 keys; the 21 endings add `is_ending` and (all 21) have `choices: []`.

The binding contract is the **345-test suite** (`python3.6 -m unittest discover -s tests` → 345 OK, verified 2026-09-04) plus two CLI gates (`tools/check_citations.py`, `tools/check_edit_coverage.py`). Roughly 20 named tests pin the bundle: 57 nodes / 21 endings (1T+3G+2N+15B) / 15 edit-allowed nodes with 14 distinct `edit:enzyme:` tags / 0 single-Continue / seed-42 shuffle fate / 13 signature round-trips / cast(12) ⊆ edits(13) == tags(14) − {tca.citrate_synthase}. The editor MUST treat node-id set, `choices[]` topology, `weight`/`cond`, `edit:enzyme:` tags, `is_ending`, `on_enter` op sequences, and edits/cast JSON as **structural** (each edit must be validated against the pin list before save) and only `text_dramatic` / `text_teaching` / `choice.label` as **safe text** — while `claim_ids`, though content-like, are **gate-checked** (any reference to a missing or non-`approved` claim fails the citation gate except the 2 sanctioned `PLACEHOLDER_PHASE8` stubs).

**Primary recommendation:** Build the editor's save path around a *validation mirror* of the owning tests (57/21/15/14/13/12 counters, dangling-goto, dangling-branch/pool, offer⇒tag, two-layer text, citation approval lookup) and a structural-vs-text field split in the UI; never let a save through that changes the frozen structural half without an explicit override.

### 1.1 `data/story_glucose/manifest.json` (14 lines)

| Key | Value (actual) | Read by |
|-----|----------------|---------|

- **Files are the ONLY bundling mechanism**: `StoryGraph.load` merges `files[i]["nodes"]` dicts; a node in an unlisted file simply does not exist (graph.py:70-87).

- **Manifest order drives the viewer's column layout**: committed viewer (git `53f9622`, `git show HEAD:tools/story_graph_viewer.py` lines 67-77) maps `intro.json→0, glycolysis.json→1, pyruvate_branch.json→2, tca.json→3, etc_atp.json→4, endings.json→5, bad_endings.json→5`; column 6 = "Phase-8 stubs" (special ids). Reordering `files` changes the diagram, not the game.
- **Adding a node NEVER needs a new file** — always into one of the 7 existing files. A new file would require a manifest edit and would land in an unmapped column (viewer `FILE_COL.get(file_of[nid], 6)` default, viewer line 336).

### 1.6 Choice schema

`{label, goto, cond?, weight?, effects?, tags?}` (Choice.from_dict, rpg/story/model.py:193-204). Presence across 95 choices: `label` 95/95, `goto` 95/95, `tags` 62/95, `effects` **key** on 4 (only ONE non-empty: pyr.branch anaerobic `{"set": {"anaerobic": true}}`), `weight` 2 (tca.shuffle 0.5/0.5), `cond` 1 (tca.shuffle cycle trap, `visits.get('tca.shuffle', 0) > 5`).

- `cond` is a restricted-namespace Python expression evaluated against `{flags, char, counters, visits}` dicts, **no builtins**; any exception → choice silently hidden (rpg/story/interpreter.py:101-135). **Dict-method form (`flags.get('x')`, `visits.get('x', 0)`) is mandatory** — `flags.x` raises AttributeError → hidden → stuck. Regression scan: test_glucose_reachability.py:716-752.
- `weight` (float, present) ⇒ RNG-decided pick among weighted choices via the single RngEngine (interpreter.py:43-73). **tca.shuffle is the ONLY weighted node** — pinned verbatim by test_glucose_content.py:539-557 (`{"tca.shuffle": [("tca.co2_turn1", 0.5), ("tca.co2_turn2", 0.5)]}`).
- `effects` → `{"set": {flag: val}, "incr": {counter: delta}}` applied to GameState (interpreter.py:137-154).
- Choices are player-selected by index when non-weighted; `engine.goto` bypasses choice resolution for special choices (rpg/engine.py:122-149, 179-193).

### 1.7 Node-kind taxonomy — DERIVED, not stored

Committed viewer `derive_kind` (git show HEAD:tools/story_graph_viewer.py:206-228), precedence first-match:

```
ending-<tier>  (is_ending not None)
> phase8-stub  (fa.stub, alc.stub — id-list)
> edit-prompt  (edit.prompt)
> restored     (gly.pfk_restored, tca.aconitase_restored — id-list)
> rng          (any choice.weight not None)
> edit-allowed (any tag startswith edit:enzyme:)
> story
```

**"Starting node"** = `manifest.start` (`intro.preface`) — a single graph entry point, not a node property. **"Multiple-choices node"** = any node with ≥2 choices (all non-ending nodes currently have ≥2; 0 single-Continue pinned). **"Mutation node"** = edit-allowed (tag). **"Ending node"** = `is_ending` present.

## 4. COMMON PITFALLS — every way an edit can break a gate

1. **Retargeting/deleting any `choice.goto`** → dangling divert (`validate_graph`) and/or orphaned ending → reachability RED (invariants 1-2). `gly.pfk_restored`/`tca.aconitase_restored` have **no inbound goto by design** — "fixing" their isolation breaks test 6.
2. **Adding an ending node** without an inbound edge → orphan RED; also bumps the 21-count pin (any topology change owes same-plan test updates — the 07-01 ledger rule).
3. **Deleting a node** → every inbound goto dangles; if it's an edits.json `branch_node` → dangling_edit_branch; if it's a pool member → dangling_pool_node; if a cast/edit/tag set changes → relationship pin.
4. **Adding a second weighted choice anywhere except tca.shuffle** → determinism contract break (test 16) — needs a documented-fate update, not a silent add.
5. **Editing a tca.shuffle weight** → seed-42 fate flips (documented fate pin) + `test_shuffle_is_the_only_weighted_node`.
6. **Writing a cond in attribute form** (`flags.host_o2_low`) → silently hides the choice at runtime (caught exception) — the exact Phase-6 SC#3 bug class; regex-scanned by test 7.
7. **Adding a claim_id that is missing/pending/rejected** → citation gate exit 1 with a new line; the sanctioned residual is EXACTLY 2 MISSING + 0 UNAPPROVED. Approving a claim = flip `approval_status` only, keep `-cand` id (M1). Never register PLACEHOLDER_PHASE8.
8. **Adding an `edit:offer` choice without the `edit:enzyme:` tag** (or vice-versa) → invariant 5; adding a 16th `edit:enzyme:` tag → invariant 4 exact-set.
9. **Adding a cast entry without an edits bucket** (or deleting a bucket that covers a cast id) → coverage gate exit 1; any set change → relationship pin 15.
10. **Reordering/duplicating a signature inside a bucket** → duplicate_signature issue; changing `branch_node` to a non-existent node → dangling_edit_branch; pointing it at a non-ending → round-trip + reachability interactions.
11. **Changing the global `bad_ending_pool` to []** → `empty_bad_ending_pool` + runtime `EditRoutingError` for every unknown edit on buckets without overrides. Pool members must be `is_ending` nodes.
12. **Blanking text / introducing "TBD"** → two-layer + TBD scans (edit.prompt's `[STRUCTURAL STUB:` marker is load-bearing — removing it lifts its exemption and fails test 9's marker test).
13. **Editing start-node on_enter** (intro.*) to a `pdb:` load → instant-start contract + start-shape tests. Hero-highlight op order is an ordered-subsequence pin.
14. **Duplicate node ids across files** → `ValueError` at load (graph.py:76-80) — the editor must check id uniqueness bundle-wide, per keystroke on rename.
15. **Treating `ending:*` tags as the tier source** → wrong: 3 anaerobic endings carry no tier tag; derive tier from `is_ending` only.
16. **Writing files with a Python-2/JSON5 dialect, or re-serializing whole files with key reordering** — tests do parsed-JSON comparison (dict equality), so key order is safe, but the 07 practice of byte-frozen structural halves (parsed-equality verified vs HEAD) recommends the editor preserve each node object's key order and emit 2-space-indented UTF-8 matching the existing files.

## 5. STATE OF THE ART / NOTES

- **Node kinds are derived (05.1-DESIGN decision, viewer-confirmed).** A single-valued `node_type` field was explicitly REJECTED (breaks multi-role nodes like tca.shuffle = rng + edit-allowed + choice). The editor should display derived kinds as computed badges, and implement transitions as the multi-field recipes in §1.7.
- **`bad_ending_pool` (edits.json, 2 entries) ≠ edit.prompt's 13 structural choices.** The former is the runtime unknown-edit roulette; the latter are never player-facing (controller intercepts edit.prompt → EditDialog). The editor must label them differently in the UI.
- **Python 3.6 tooling constraint** applies to any generator script the editor pipeline might add (no f-strings in tools/); the HTML editor itself is dependency-free JS (no build step, no CDN — offline requirement).
- **Phase 12 reminder (Req B-9):** ending CG is not represented anywhere in the current data (no `cg` field); if the editor adds a placeholder field, it must be one the loader ignores (`Node.from_dict` uses `.get` for known keys and ignores unknowns — graph.py/model.py tolerate extra keys, but keep it out of the frozen files until Phase 12 defines it).

## Open Questions

1. **Save format/round-trip guarantee** — should the editor preserve raw file byte-order of nodes within `nodes{}`? Parsed-equality is what tests check; byte-diff cleanliness is a UX nicety. Recommendation: preserve insertion order, 2-space indent, trailing newline (matches current files).
2. **Where scene camera/color/representation paste-in lands (Req B-8)** — recommendation: paste as validated `on_enter` MolAction blocks (op vocabulary §1.4) appended after the existing sequence; never reorder existing ops of pinned nodes (start nodes, restored nodes).
3. **Undo/redo scope across multiple files** — an edit to tca.json + edits.json + cast.json is one logical change (the relationship pin); the editor's undo unit should be the whole bundle snapshot, not per-file.
