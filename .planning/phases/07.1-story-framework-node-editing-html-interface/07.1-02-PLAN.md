1. **Byte-identical no-op oracle**: for each of the 12 targets — `data/story_glucose/manifest.json`, the 7 story files, `data/citations.json`, `data/sources.json`, `rpg/data/edits.json`, `rpg/data/cast.json` — `dumps(json.load(raw)) + "\n" == raw` (UTF-8 read/write).
2. **Encoding basics**: `ensure_ascii=False` (em-dashes in story text stay literal UTF-8), 2-space indent, trailing newline appended by the caller or `dumps` — pin which (recommend: `dumps` returns WITHOUT trailing newline; file write adds it; test asserts the contract).
3. **Raw float preservation**: floats keep their source literal (`2.40` stays `2.40`, not `2.4` — citations.json resolution_angstrom). Implement via `json.loads(..., parse_float=RawFloat)` where RawFloat wraps the token string; `dumps` emits the raw token. (JS-side note lives in 07.1-05; writable targets have no such floats.)
4. **Scalar lists** (no dict/list elements): inline iff `indent + len(compact_form) <= 110` else multiline — e.g. `"claim_ids": ["GLY-INTRO-01"]` inline; manifest `files` (compact 130) multiline.
5. **Container arrays** (any dict/list element): ALWAYS multiline array; each container element inlined iff it itself `fits` (rule 6) — e.g. on_enter `[{"op": "hide_all"}]` breaks but its element renders inline; cast.json enzymes (compact 137-171, indent 4) all inline; choices elements inline up to width ≤ 175.
6. **Dict inline rule (`fits`)**: `indent + len(compact(v)) <= 175` AND the dict contains **no container-array child** (arrays of containers are always multiline, so an inlined dict may not contain one) AND every descendant container `fits` at its own depth (propagation). Multiline dicts render children at +2 indent, close brace at parent indent.
7. **`edits` hand-style exception**: array elements under the key `edits` (edits.json) are ALWAYS multiline dicts (each field own line; the `signature` dict inlines per rule 6). Implemented as a parent-key force flag flowing into the element render (verified: without it edits.json fails; with it 12/12 pass).
8. **Empty containers**: `{}` and `[]` always inline.
9. **fixture_vectors()**: returns a list of `(name, python_object, expected_string)` triples covering the tricky cases: inline claim_ids; multiline long scalar list; on_enter with inline elements; long element that breaks (>175); edits-style entry; nested empty dict/list; float 2.40; non-ASCII string; unicode-free string with quotes/backslashes. These vectors are the shared spec for the JS port (07.1-05 embeds the same expectations).
