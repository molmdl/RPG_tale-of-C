3. **Folder pick**: `<input type="file" webkitdirectory multiple>` mounted into the boot panel. On change: iterate `File.webkitRelativePath`; REJECT any path containing `..`, a drive letter (`/^[A-Za-z]:/`), or a leading `/`; match against EXPECTED via `/`-boundary suffix match (a parent-of-repo pick works; a child-folder pick matches nothing by design → checklist says "select the repository root"); never enumerate `.git` contents (filter, don't iterate blindly — Pitfall 3c); load matched files via FileReader.readAsText.
4. **Manifest-driven completion**: after manifest + registry/edits/cast are in hand, require the manifest's 7 `files` entries under `data/story_glucose/`; any missing → the checklist banner marks it ✗ with the expected tree; ALL required present → assemble `bundle` ({files, manifest, citations, sources, edits, cast, order}) and call `EDITOR.setBundle(bundle, rawTexts)`; optional-degrade: cast load failure degrades with a warning (viewer convention), citations/sources missing → warnings (claims panel degrades), edits.json missing → BLOCK (it is a required edit target).
5. **Checklist banner**: one row per expected path with ✓/✗ + the friendly hint per RESEARCH-UI step 3; stays visible (collapsible) after load.
6. **Draft reload**: single `<input type="file" accept=".json,application/json">` labeled "Load draft…"; parses the draft bundle `{version, saved_at, bundle, dirty, undo_meta, fingerprints}` → `EDITOR.setBundle` with the draft's per-file content; fingerprint comparison vs freshly picked folder files → warn "underlying files changed since this draft" when both available (full stale-draft UX completes in 07.1-13; this plan provides the load + warn hook point `EDITOR.load.onDraftLoaded`).
7. **Duplicate-key guard**: JSON.parse cannot detect duplicate keys; for the REGISTRIES (citations/sources) run a lightweight duplicate-key scan of the raw text at top level (regex-free: walk with a tiny depth-1 key collector or use a reviver that throws on repeated keys via a seen-set per object level — implement a `parseNoDupKeys(text)` using JSON.parse with a `seen` WeakSet... simplest correct approach: a small hand parser is overkill; use a reviver that counts keys per object via a Map keyed by object identity is impossible in revivers — instead pre-scan top-level keys with a regex on line starts `"KEY": {` and flag duplicates; document the approximation). Registry duplicate claim_ids must be detected on load (RESEARCH-DATA §3 row 4).
8. Inject CSS for the boot panel/checklist. ES5 only. Header comment: ownership 07.1-07; cite RESEARCH-UI Persistence + CVE-2019-11730 in the probe comment.
