## Decisions Made
See `key-decisions` in the frontmatter; the load-bearing ones:
- **Dirty map, not array (Rule 1 compatibility fix):** the plan's draft shape said `dirty: [fnames]`, but the already-landed loader restores `draft.dirty` as an object map — emitting an array would restore index strings ("0", "1", …) as dirty file names and corrupt the dirty state. The map carries identical information (keys ARE the fname list) and is documented in-source with the consumer citation.
- **All baselines move on the explicit confirm:** mark-saved resets `_originals` (dirty baseline), `fingerprints`, and the load layer's `folderRawByFname` to the downloaded body — one human assertion, three coherent baselines; a later re-pick re-derives reality.
- **Work-protected discard:** the S3 "Discard" option rebuilds from folder raws only when it cannot destroy work (no in-session edits — detected via undo/redo depths, which `setBundle` resets at draft load); otherwise guidance, never silent loss.
- **Byte-identity proven, one documented exception:** the runtime smoke proves every writable save body byte-identical to the repo file EXCEPT intro.json's single `rgb [0.0, …]` token (the JS JSON.parse integral-float loss) — shown honestly in the panel + header, fix flagged for the human (below).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Draft `dirty` emitted as an object map instead of the plan's `[fnames]` list**

- **Found during:** Task 1 (draftDoc implementation against the landed loader)
- **Issue:** 10_load.js `loadDraft` (:1092-1098) restores `draft.dirty` with `for (var k in draft.dirty) { state.dirty[k] = true; }` — a for-in over the plan's array form would iterate INDICES ("0", "1", …) and mark files named "0"/"1" dirty, corrupting the dirty state on every draft reload.
- **Fix:** `draftDoc()` emits `dirty` as `{fname: true}` — identical information (keys = the fname list), correct under the landed consumer; documented in-source as a SHAPE NOTE citing `10_load.js loadDraft :1092-1098` and pinned by `test_draft_doc_shape`.
- **Files modified:** tools/story_editor_assets/80_save.js
- **Verification:** runtime smoke S2 (`draft_dirty_is_map`) + the round-trip through a fired draft load (S7/S8)
- **Committed in:** efa8b71 (Task 1 commit)

### Flagged, NOT implemented (Rule 4 — architectural decision owed to the human)

**2. [Rule 4 - Architectural] intro.json's `rgb [0.0, 0.75, 0.75]` re-serializes as `[0, 0.75, 0.75]`**

- **Found during:** Task 1 verification (48-check runtime smoke, S3 byte-identity)
- **Issue:** JS `JSON.parse` has no parse_float hook — the `.0` of integral-float tokens is lost AT LOAD TIME (10_load.js parses with plain JSON.parse), so any later `EDITOR.housy.stringify` re-emits the shortest form. The no-op-save byte-identity property therefore fails for exactly ONE token in the writable set (intro.json's hero rgb line; Python `json.dumps` would re-emit `0.0`, and 07.1-05's "writable targets are float-free" note is factually wrong for intro.json). Same documented class as citations.json's read-only "2.40" resolution tokens.
- **Impact:** LOW — same numeric value (0 == 0.0; the engine's color math is unaffected); the only cost is one noisy extra line in the `git diff` when intro.json is edited and saved. Verified the divergence is EXACTLY one token via a Python simulation (integral-float collapse + canonical dump == raw everywhere else).
- **Why not fixed here:** the fix (lossless float-token parse — e.g. a number-token pre-scan + RawFloat-wrapper reviver, which `EDITOR.housy.rawFloat` already supports) belongs in the LOADER's parse sites (10_load.js data loads + draft reload, plus this asset's crash-copy restore) — a cross-asset change to a completed, structurally-pinned sibling plan's asset. Not attempted unilaterally.
- **Mitigation shipped (in scope):** the save panel + asset header document the limitation and name the exact affected line; the post-save reminder already mandates the `git diff` review.
- **Recommended follow-up:** a small plan adding a lossless float-token parse helper to the load layer (data + draft + crash-copy parse sites) with 07.1-07's battery extended; alternatively the human accepts the one-line diff noise.
